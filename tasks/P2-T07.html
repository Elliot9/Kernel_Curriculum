P2-T07 · bitmap 與點陣圖在 kernel 的應用

一句話:用一個 bit 代表一個資源的「已用/空閒」,一塊小小的點陣圖就能高效管理成千上萬個資源的配置狀態。kernel 用它做 CPU 遮罩、區塊配置——而 blk-mq 的 tag(sbitmap)正是用它管理你產品的 in-flight I/O 請求。

為什麼要先學這個(導讀)

這一課把你在 P0-T11 學的位元操作,提升成一個 kernel 天天用的實用工具——bitmap(點陣圖)。

核心想法極簡單:用每一個 bit 代表「一個資源」的狀態(1 = 已用,0 = 空閒,或反過來)。要管理 1000 個資源的「哪些被用了、哪些還空著」,你不需要 1000 個 bool(那要 1000 bytes),只要 1000 個 bit(125 bytes)就夠——而且檢查、設定、清除某個資源的狀態,都是飛快的位元操作(回顧 P0-T11 的 set/clear/test bit)。

kernel 大量使用 bitmap: - cpumask:用一個 bitmap 表示「哪些 CPU 核心」(每個 bit 對應一個核心),用於 CPU 親和性(這個工作該在哪些核心上跑)。 - 區塊配置:用 bitmap 記錄「哪些區塊/槽位被配置了」。 - find first/next bit:在 bitmap 裡快速找「第一個是 0 的 bit」(第一個空閒資源)或「下一個是 1 的 bit」。

為什麼這對你是 scope: direct?因為 blk-mq(你產品依賴的多佇列區塊層框架)用「tag」管理 in-flight 的 I/O request,而 tag 的底層是 sbitmap(scalable bitmap,可擴展點陣圖)。每個正在處理的 I/O 請求佔一個 tag(一個 bit),完成就釋放。NVMe 的佇列深度也靠類似機制。這一課的 bitmap 配置器,正是理解 P5 tag 機制的前置——你會看到「配置一個 tag = 在 bitmap 找第一個空閒 bit 並設為 1」。

開始之前(前置確認)

  • 依賴:P0-T11(位元操作——set/clear/test bit、遮罩),這課是它的 kernel 實用化。
  • 自我檢測: 1. 你還記得 P0-T11 怎麼用 flags |= (1<<n) 設定第 n 位、flags & (1<<n) 檢查第 n 位嗎?bitmap 就是這些操作的大規模、多字版本。 2. 你還記得 P1-T08/P1-T10 的原子操作嗎?這課的 set_bit(原子)vs __set_bit(非原子)直接用到。

1. 核心想法:用一個 bit 代表一個資源的狀態

最基本的概念:你有 N 個資源(槽位、ID、CPU 核心……),用一塊有 N 個 bit 的記憶體,第 i 個 bit 代表第 i 個資源的狀態。

操作直接對應 P0-T11 的四招(只是現在「第 n 位」代表「第 n 個資源」): - 配置資源 i:把 bit i 設為 1(set_bit)。 - 釋放資源 i:把 bit i 清為 0(clear_bit)。 - 檢查資源 i 是否已用:測 bit i(test_bit)。

這個表示法省空間又快速,所以 kernel 用它管理大量同類資源的配置狀態。

2. 多字 bitmap:為什麼要用 kernel API,別自己操作

P0-T11 你操作的是「一個整數內的位元」(例如一個 unsigned int 的 32 個 bit)。但 kernel 的 bitmap 常常遠超一個整數的位元數(例如 1000 個 bit,需要好幾個 64-bit 字來裝)。這種「跨多個字(word)」的 bitmap,手動操作很容易出錯。

kernel 提供完整的 bitmap API(在 include/linux/bitmap.h 與 bitops.h):set_bit(n, map)、clear_bit(n, map)、test_bit(n, map)、以及第 3 節的 find 系列。你只需給「第幾個 bit」,API 自動處理「那是哪個字的哪一位」的細節(它幫你算 n / 64 是哪個字、n % 64 是字內哪位)。

「手動用 <</& 操作多字 bitmap 而非用 kernel API」是常見誤區——對單一整數的位元用 P0-T11 的手法沒問題,但跨多字的 bitmap 一定要用 API,否則極易出錯(算錯字、越界)。

3. find first/next bit:快速找空閒資源

bitmap 最重要的「進階」操作,是快速掃描:在一大塊 bitmap 裡找「第一個 0」(第一個空閒資源)或「第一個 1」(第一個已用資源),或從某位置開始找「下一個」。

最常用的是 find_first_zero_bit:配置資源時,你要找「第一個空閒的」,就是找第一個 0 的 bit,把它設為 1,回傳它的索引。這些 find 函式是高度優化的(底層用 CPU 指令一次掃一整個字,跳過全 1 或全 0 的字),比你自己寫「逐 bit 檢查」的迴圈快得多。

連到你的工作:blk-mq 配置一個 tag,核心動作就是「在 tag 的 bitmap 裡 find_first_zero_bit 找一個空閒 tag,設為已用,回傳 tag 編號」。釋放就是 clear_bit。你現在懂了 tag 配置的底層機制(第 6 節會親手實作一個簡化版)。

4. cpumask:bitmap 的招牌應用

kernel 最常見的 bitmap 應用之一是 cpumask——用一個 bitmap 表示「一組 CPU 核心」,每個 bit 對應一個核心(bit i = 1 代表「包含 CPU i」)。

cpumask 用 bitmap 表示「一組核心」,常用於 CPU 親和性——指定「某個工作、某個中斷、某條 I/O 佇列」可以在哪些 CPU 上執行。這直接呼應 P1-T03:NVMe 多佇列「每個核心一條佇列」、per-CPU 設計,都需要用 cpumask 來指定「這條佇列綁哪個核心」。kernel 有專門的 cpumask API(在 include/linux/cpumask.h),本質上是 bitmap API 的特化版,加上「CPU 數量」的語意。

理解 cpumask = 一個「CPU 集合的 bitmap」,你就能讀懂 kernel 裡大量「這個東西在哪些 CPU 上」的程式碼,包括你產品 I/O 佇列與核心綁定的部分。

5. set_bit(原子)vs __set_bit(非原子):何時用哪個

這是一個直接關係正確性的關鍵區分,呼應你 Phase 1 的並行知識(P1-T08 race、P1-T10 原子操作)。

kernel 的位元操作有兩個版本:有底線前綴的(__set_bit)和沒有的(set_bit)。差別在原子性:

關鍵理解:為什麼非原子版在並行下會 race? 因為「設定一個 bit」底層是「讀出那個字 → 改一個 bit → 寫回」(回顧 P1-T08 的讀-改-寫!)。如果兩個核心同時設定同一個字裡的不同 bit,它們的讀-改-寫會交錯,一個的修改可能覆蓋另一個——即使它們設的是不同 bit(因為它們讀寫的是同一個字)。這跟 P1-T08 的 count++ race 是同一個道理。

所以規則是:bitmap 若會被並行修改(多核心、中斷處理常式),用原子版 set_bit/clear_bit;若你已經用其他鎖保護了、或確定只有單一執行流碰它,用非原子版 __set_bit 省開銷。「忽略並行下需要原子位元操作」是常見且危險的誤區——選錯版本,bitmap 會悄悄損壞(回顧 P1-T08 race 的「時有時無、難 debug」)。

6. 實作一個 bitmap 配置器

把前面所有東西組起來,實作一個簡單的資源配置器——這正是 blk-mq tag 配置的簡化原型。

② 把它 set 為 1(標記已用)
③ 回傳那個 bit 的索引(= 配到的資源編號)"]
        FREE["free(i):

    allocator --> BEHAVIOR
    TAG["= blk-mq tag 配置的原型:

    BEHAVIOR --> TAG
    style ALLOC fill:#e8a33d,color:#10100e
    style TAG fill:#8a9a5b,color:#10100e

配置器的邏輯: - alloc():用 find_first_zero_bit 找第一個空閒(0)的 bit → 設為 1 → 回傳索引。因為總是找「第一個」空閒的,連續配置會回傳遞增的最小空閒索引。 - free(i):把 bit i 清為 0。之後再 alloc,find_first_zero_bit 會找到這個剛釋放的(若它是最小的空閒),達成重用。

這就是 blk-mq tag 配置的原型:把「資源」換成「tag」(代表一個 in-flight I/O 請求的槽位),alloc 就是「為一個新 I/O 請求分配一個 tag」,free 就是「I/O 完成、釋放 tag」。NVMe 的佇列深度上限,本質就是「tag bitmap 有多少個 bit」(同時最多多少個 in-flight 請求)。你親手做這個配置器,就摸到了 P5 tag 機制的核心。

(真實的 blk-mq 用的是 sbitmap——一個為了在多核心下減少競爭而做的「可擴展 bitmap」,它把大 bitmap 切成多塊、配合 per-CPU 等技巧來避免 false sharing,呼應 P1-T03。但核心概念就是你做的這個 bitmap 配置器,sbitmap 是它的多核優化版。)

一句話總結:bitmap 用一個 bit 代表一個資源的狀態,省空間又能用飛快的位元操作管理大量資源;kernel 用它做 cpumask(CPU 親和性)、區塊配置,並提供 find-first-zero 等優化函式;並行下務必用原子版 set_bit(否則讀-改-寫 race);而「find-first-zero + set」的配置器,正是你產品 blk-mq tag(sbitmap)管理 in-flight I/O 的原型——這是 P5 tag 機制的前置。

常見誤區與踩雷提醒

誤區一:手動用 <</& 操作多字 bitmap 而非用 kernel API。 單一整數的位元用 P0-T11 手法沒問題;但跨多字的 bitmap 要用 set_bit/find_first_zero_bit 等 API,否則容易算錯「哪個字、字內第幾位」或越界。

誤區二:忽略並行下需要原子位元操作。 bitmap 若被多核心/中斷並行修改,要用原子版 set_bit/clear_bit;用非原子的 __set_bit 會 race(讀-改-寫交錯,回顧 P1-T08),bitmap 悄悄損壞。

誤區三:越界存取超出 bitmap 宣告的位元數。 bitmap 有固定的 bit 數;存取超過範圍的 bit 是未定義行為(回顧 P0-T10)。用 API 時傳對 size,別超界。

誤區四:以為 __set_bit(非原子)永遠該避免。 不是。在「已有外部鎖保護」或「確定單一執行流存取」時,非原子版更快、是正確選擇。關鍵是判斷有沒有並行存取。

動手實作

環境:Linux 終端機,使用者態,安全,不需 root、不動系統。(可用 P0-T11 的位元操作自己實作 bitmap,或用 user space 的 bitmap 概念。)

任務 A — 實作 bitmap 配置器(驗收點) 用一塊 bitmap(可以是一個 unsigned long 陣列,或先用單一整數簡化)實作: - alloc():找第一個是 0 的 bit(第一個空閒),設為 1,回傳索引。 - free(i):把 bit i 清為 0。 測試:連續 alloc N 次,確認回傳遞增的最小空閒索引(0, 1, 2, ...)。(找第一個 0 的 bit,可先用 P0-T11 的 test bit 逐位檢查,理解原理;再了解 kernel 有優化的 find_first_zero_bit。)

任務 B — 驗證重用(驗收點) 承任務 A:alloc 幾個(例如得到 0,1,2),然後 free 中間一個(例如 free(1)),再 alloc 一次——確認它重用了剛釋放的索引 1(因為 find-first-zero 會找到它)。驗收:釋放後再配置能重用該索引。

任務 C — 說明原子 vs 非原子(驗收點) 用一句話說明:set_bit(原子)和 __set_bit(非原子)各該在什麼情況用?為什麼非原子版在並行下會出錯?(提示:設 bit 是讀-改-寫,回顧 P1-T08;兩核心改同一個字裡的不同 bit 會互相覆蓋。)驗收:能說出選擇依據與 race 原因。

任務 D(連結)— 連到 blk-mq tag 寫一兩句話:你的 bitmap 配置器,如何對應到「blk-mq 用 tag 管理 in-flight I/O 請求」?(提示:tag = 一個 bit;配置 tag = find-first-zero + set;I/O 完成 = clear。)

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 用 bitmap 實作配置器,連續配置 N 個資源各回傳遞增的最小空閒索引。 2. ☐ 釋放其中一個後再配置,能重用該索引(find-first-zero)。 3. ☐ 說明 set_bit(原子)與 __set_bit(非原子)何時各該用。

評分量表: - 60(及格):能用 bitmap(set/clear/test）。 - 80(熟練):能實作 bitmap 配置器(alloc/free/重用)。 - 100(精通):能連結到後續區塊層/NVMe 的 tag 配置(sbitmap)。

延伸與銜接

  • 對應工作場景:直接對應——blk-mq 用 tag(sbitmap)管理 in-flight request;NVMe 佇列深度也靠類似配置。此 task 是理解 P5 tag 機制的前置。cpumask 則關係你 I/O 佇列與 CPU 核心的綁定(呼應 P1-T03)。
  • 這課餵給未來的:bitmap 配置器 → P5 blk-mq 的 tag/sbitmap;cpumask → CPU 親和性、多佇列綁核;原子位元操作 → 回收 P1-T08/P1-T10,並用於 kernel 並行旗標。

P6-T04 · IOMMU 與 VFIO

一句話:IOMMU 是「裝置端的 MMU」——它把裝置發出的 DMA 位址做轉譯與保護(讓分散實體頁對裝置呈現連續、擋掉裝置亂存取的記憶體)。這就是 dma_addr_t 背後的轉譯者。而 VFIO 靠 IOMMU 的隔離,把裝置安全地直通給 user space 或 VM——但要以 IOMMU group 為單位。

為什麼要先學這個(導讀)

P6-T01/P6-T02 你一直碰到「IOMMU 在背後轉譯 dma_addr_t、合併分散片段」。這一課正面講清楚 IOMMU 是什麼,以及建立在它之上的 VFIO(裝置直通)。

IOMMU(I/O Memory Management Unit) 是「裝置端的 MMU」——做一個漂亮的類比(回顧 P1-T04 MMU): - MMU:在 CPU 和記憶體之間,把 CPU 的虛擬位址轉成實體位址,並提供行程隔離保護。 - IOMMU:在裝置和記憶體之間,把裝置的 DMA 位址(dma_addr_t) 轉成實體位址,並提供裝置的隔離保護。

IOMMU 做兩件關鍵的事: - 位址轉譯:把裝置看到的 DMA 位址,轉成實體位址——這就是為什麼 dma_addr_t ≠ 實體位址(P6-T01 鐵則的根源)。它還能把分散的實體頁,對裝置呈現成連續(回顧 P6-T02 的合併)。 - 保護隔離:限制裝置只能存取「被允許的」記憶體——惡意或故障的裝置不能亂 DMA 到任意記憶體(這對安全極重要)。

還有兩個概念: - IOMMU group:隔離的最小單位——同一個 group 裡的裝置無法彼此隔離,所以要直通就得整組一起。 - VFIO(Virtual Function I/O):利用 IOMMU 的隔離,把裝置安全地直通給 user space 或 VM(user space 驅動、passthrough)。

為什麼這對你是 scope: direct?三個層面:① IOMMU 影響你 DMA 的位址轉譯(dma_addr_t 的由來);② 若你產品涉及 user space 驅動或 VM 直通 NVMe/GPU,VFIO 與 IOMMU group 是必備知識;③ P2PDMA 的可行性與 IOMMU 設定相關(P6-T05 出關門檻——我已查證:有 IOMMU 時 root-complex 白名單會被停用,P2P 路徑與 IOMMU 設定強相關)。

核心類比: - MMU(CPU 端,P1-T04):CPU 虛擬位址 → 實體位址 + 行程隔離。 - IOMMU(裝置端):裝置 DMA 位址 → 實體位址 + 裝置隔離。

IOMMU 就是「裝置版的 MMU」——對象是裝置(而非 CPU),轉譯的是 DMA 位址(而非虛擬位址),隔離的是裝置(而非行程)。理解這個對應,IOMMU 的兩個功能(轉譯、保護)就都好懂了——它們正是 MMU 兩個功能的裝置版。

常見誤區:把 IOMMU 位址轉譯與 MMU 的行程分頁混為一談——它們對象不同:MMU 服務 CPU(行程的虛擬記憶體),IOMMU 服務裝置(裝置的 DMA)。兩者機制類似(都是位址轉譯 + 保護)、但作用對象完全不同。別把它們當成同一個。

2. 位址轉譯:dma_addr_t 的由來

IOMMU 的第一個功能:位址轉譯——這正是 P6-T01 鐵則「dma_addr_t ≠ 實體位址」的根源。

位址轉譯:裝置發出 DMA 用 dma_addr_t,IOMMU 查它的轉譯表(類似 MMU 的分頁表,P1-T04),把 dma_addr_t 轉成實體位址,再存取記憶體。它還能合併(回顧 P6-T02):把分散的實體頁,在 IOMMU domain 裡映射成連續的 dma_addr 範圍——裝置看到連續,DMA 更簡單。

這解釋了你前面碰到的所有「dma_addr_t 的怪事」: - dma_addr_t ≠ 實體位址——中間有 IOMMU 轉譯。 - dma_addr_t 不能 CPU 解參考——它是 IOMMU domain 的位址,CPU 的位址空間裡無意義(P6-T01 鐵則)。 - dma_map_sg 映射數變少——IOMMU 把分散頁合併成連續(P6-T02)。

你「位址的真相」主線到這裡完全閉環:位址不是絕對數字,而是「誰看、經過什麼轉譯」——CPU 經 MMU、裝置經 IOMMU。dma_addr_t 是「裝置經 IOMMU 看到的位址」,這就是它的完整身份。

3. 保護隔離:擋掉裝置亂存取

IOMMU 的第二個功能,對安全極重要:保護隔離——限制裝置只能存取「被允許的」記憶體。

保護隔離: - 沒有 IOMMU:裝置能 DMA 到任意實體位址——惡意/故障裝置可亂讀寫任何記憶體(讀核心機密、竄改核心),安全風險。 - 有 IOMMU:IOMMU 只在轉譯表裡建立「被允許的」映射——裝置只能存取映射過的記憶體;DMA 到未映射的位址 → IOMMU 擋下(fault)。

價值(驗收點:說明 IOMMU 如何同時提供「位址轉譯」與「保護隔離」): - 安全:擋掉惡意/故障裝置的越界 DMA。 - 隔離:把裝置直通給 VM/user space 時,裝置只能碰被指派的記憶體(VFIO 的基礎,第 5 節)。

所以 IOMMU 同時做轉譯和保護——就像 MMU 同時做轉譯和行程隔離。轉譯讓裝置用乾淨的連續位址,保護讓裝置不能亂來。這兩個功能是一體的(都靠 IOMMU 的轉譯表:表裡有的才能存取、且按表轉譯)。

常見誤區:以為關掉 IOMMU 一定更快——關掉 IOMMU 省了轉譯開銷,看似更快,但犧牲了隔離與保護,而且某些場景(如 P2PDMA、VM 直通)需要它。不能無腦關。是否關 IOMMU 是「效能 vs 安全/功能」的權衡,不是「關了一定好」。

IOMMU group:一組「無法彼此隔離」的裝置(因為硬體拓樸——例如同一個 PCIe switch 下、或共用某些路徑的裝置,IOMMU 無法區分它們的 DMA 來源)。

規則(驗收點之一):隔離以 group 為單位——group 內的裝置無法彼此隔離,所以要把裝置直通(交給 VM/user space),必須整個 group 一起直通,不能只直通其中一個。

查看:/sys/kernel/iommu_groups/——每個編號目錄是一個 group,裡面列出成員裝置(驗收點:列出系統至少一個 IOMMU group 及其成員)。

常見誤區:忽略 IOMMU group 的隔離邊界——你想直通一個 NVMe,但它和別的裝置在同一 group → 必須整組一起直通(否則隔離被破壞)。規劃直通時要先看 group 邊界。

這對你產品很實際:若你要把某個 NVMe 或 GPU 直通給 VM/user space 驅動,得先確認它的 IOMMU group——同 group 的裝置要一起處理。這也影響 P2PDMA 的拓樸規劃(P6-T05)。

5. VFIO:把裝置安全地直通給 user space

建立在 IOMMU 隔離之上的就是 VFIO(Virtual Function I/O)——把裝置安全地直通給 user space 或 VM。

    NEED5["需求:讓 user space 程式(或 VM)直接驅動一個裝置

    NEED5 --> RISK2["風險:user space/VM 直接控制裝置 → 能讓裝置 DMA
→ 若無保護,裝置可亂 DMA 到任意記憶體(危險)"]
    RISK2 --> VFIO2["★ VFIO 的解法:用 IOMMU 提供安全保證 ★
① IOMMU 限制這個裝置只能 DMA 到

② user space 透過 VFIO 介面安全地操作裝置
→ 即使 user space 出錯/惡意,裝置也碰不到別的記憶體"]
    VFIO2 --> REQUIRE["★ 要求(驗收點):裝置要直通,需屬於可隔離的 IOMMU group ★
(整個 group 一起綁到 VFIO,第4節)"]

    style VFIO2 fill:#8a9a5b,color:#10100e

VFIO 解決「讓 user space/VM 直接驅動裝置」的安全問題: - 需求:user space 程式(或 VM)直接驅動一個裝置(user space 驅動、把 NVMe/GPU 直通給 VM)。 - 風險:user space/VM 直接控制裝置 → 能讓裝置 DMA → 若無保護,裝置可亂 DMA 到任意記憶體(危險)。 - VFIO 的解法:用 IOMMU 提供安全保證——IOMMU 限制這個裝置只能 DMA 到「user space/VM 被指派的記憶體」;即使 user space 出錯/惡意,裝置也碰不到別的記憶體。

要求(驗收點:說明 VFIO 直通對 IOMMU group 的要求):裝置要直通,需屬於可隔離的 IOMMU group——整個 group 一起綁到 VFIO(第 4 節)。沒有 IOMMU 的隔離,VFIO 的安全保證就不成立。

對你產品:如果你的產品架構用 user space 驅動(在 user space 直接操作 NVMe,類似 SPDK 的做法)或 VM 直通,VFIO 就是核心機制——它讓 user space 安全地控制裝置 + 做 DMA。這也是高效能儲存常見的架構(繞過 kernel 的開銷)。理解 VFIO + IOMMU group,你才能評估這條路。

6. 與 SR-IOV 的關係

最後一個相關概念(概念層即可):SR-IOV——讓一個實體裝置「分身」成多個虛擬裝置。

    style RELATION fill:#8a9a5b,color:#10100e

SR-IOV(Single Root I/O Virtualization):一個實體 PCIe 裝置(PF,Physical Function)能分出多個輕量的虛擬裝置(VF,Virtual Function)。每個 VF 看起來像獨立的 PCIe 裝置,可各自直通給不同的 VM/user space——一張卡服務多個 VM。

與 IOMMU/VFIO 的關係:每個 VF 可有自己的 IOMMU 隔離,透過 VFIO 直通給不同 VM。所以 SR-IOV 提供「多個可直通的虛擬裝置」,IOMMU/VFIO 提供「安全直通的機制」——兩者配合,實現「一張實體卡安全地服務多個 VM」。

(這是概念層的認識,你產品不一定用到 SR-IOV;但理解它有助於完整理解「裝置虛擬化/直通」的全貌——VF 是被直通的對象,IOMMU/VFIO 是直通的安全機制。)

一句話總結:IOMMU 是「裝置端的 MMU」——做位址轉譯（dma_addr_t → 實體位址、合併分散頁，正是 dma_addr_t ≠ 實體位址的根源）和保護隔離（擋裝置越界 DMA）；隔離以 IOMMU group 為單位（同 group 要直通就整組一起，查 /sys/kernel/iommu_groups/）；VFIO 利用 IOMMU 隔離把裝置安全直通給 user space/VM（需可隔離的 group），SR-IOV 則讓一卡分多個可直通的 VF。這影響你 DMA 的位址轉譯、user space 驅動/VM 直通的可行性，以及 P2PDMA 的設定。

常見誤區與踩雷提醒

誤區一:以為關掉 IOMMU 一定更快。 關掉省轉譯開銷,但犧牲隔離與保護,且某些場景(P2PDMA、VM 直通)需要它。是「效能 vs 安全/功能」的權衡,不是「關了一定好」。

誤區二:忽略 IOMMU group 的隔離邊界。 同 group 的裝置無法彼此隔離,要直通就得整組一起。規劃直通(VM/user space)前先看 group 邊界。

誤區三:把 IOMMU 位址轉譯與 MMU 的行程分頁混為一談。 對象不同:MMU 服務 CPU(行程虛擬記憶體),IOMMU 服務裝置(裝置 DMA)。機制類似但作用對象完全不同。

動手實作

環境:Linux(查 IOMMU group,安全)+ QEMU(實驗只在 VM)。

任務 A — 列出 IOMMU group(驗收點) 在 Linux 上(需開啟 IOMMU,如 intel_iommu=on/amd_iommu=on)查看 /sys/kernel/iommu_groups/——列出至少一個 IOMMU group 及其成員裝置(ls /sys/kernel/iommu_groups/<N>/devices/)。驗收:列出系統至少一個 IOMMU group 及其成員裝置。(若你的環境沒開 IOMMU,理解結構與意義即可。)

任務 B — 說明轉譯與保護(驗收點,核心) 用一段話說明:IOMMU 如何同時提供「位址轉譯」與「保護隔離」?驗收:說明(轉譯:把裝置 DMA 位址轉成實體位址、可合併分散頁;保護:只允許裝置存取映射過的記憶體,擋越界 DMA;兩者都靠 IOMMU 的轉譯表)。

任務 C — VFIO 對 IOMMU group 的要求(驗收點) 閱讀 VFIO 文件(https://docs.kernel.org/driver-api/vfio.html ），寫一段話:一個裝置要直通(VFIO),為什麼需先屬於可隔離的 IOMMU group?驗收:說明 VFIO 直通對 IOMMU group 的要求(需整組可隔離,否則安全保證不成立)。

任務 D(連結)— 對應你的產品 寫一兩句話:IOMMU 如何解釋你前面碰到的「dma_addr_t ≠ 實體位址、dma_map_sg 映射數變少」?若你產品用 user space 驅動操作 NVMe,VFIO/IOMMU 扮演什麼角色?

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 列出系統至少一個 IOMMU group 及其成員裝置。 2. ☐ 用一段話說明 IOMMU 如何同時提供「位址轉譯」與「保護隔離」。 3. ☐ 說明 VFIO 直通對 IOMMU group 的要求。

評分量表: - 60(及格):能查 IOMMU group。 - 80(熟練):能解釋 IOMMU 的轉譯與保護。 - 100(精通):能說明 VFIO/passthrough 與 IOMMU group 隔離的關係。

延伸與銜接

  • 對應工作場景:直接對應——IOMMU 影響你 DMA 的位址轉譯;若產品涉及 user space 驅動或 VM 直通 NVMe/GPU,VFIO 與 IOMMU group 是必備知識;且 P2PDMA 的可行性與 IOMMU 設定相關。
  • 這課收束了(位址的真相主線):P0-T05 指標 → P1-T04 虛擬/實體 + MMU → P3-T06 線性映射 → P6-T01 三種位址 + dma_addr_t → 本課 IOMMU(dma_addr_t 的轉譯者)。你完全理解了「位址 = 誰看、經過什麼轉譯」。VFIO → 你產品若走 user space 驅動;IOMMU 設定 → P6-T05 P2PDMA 可行性。
  • 下一步 → P6-T05 Peer-to-Peer DMA(p2pdma)——NVMe↔GPU 直通的核心:這是 Phase 6 的出關門檻,也是你產品的關鍵技術。你已經懂 DMA、屏障、IOMMU——下一課把它們用到產品的核心場景:P2PDMA,讓 NVMe 和 GPU 直接互傳資料,不經過 host DRAM(回顧 P5-T07 預告的前沿)。你會學:P2PDMA 原理(兩個 PCIe 裝置間直接 DMA)、NVMe CMB 與裝置 BAR、kernel p2pdma 子系統(pci_p2pdma_add_resource)、以及關鍵的限制(拓樸:需共同 switch/root port 支援;IOMMU 設定;user space p2pdma 自 6.2 進 mainline、僅 NVMe O_DIRECT——我已查證)。這直接決定你產品「DMA 把 NVMe queue I/O 餵給 GPU」資料路徑的設計。

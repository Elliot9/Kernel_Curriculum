P7-T03 · RAID-6 parity 數學(GF(2⁸) Reed-Solomon)

一句話:RAID-6 用兩個 parity(P + Q)容忍兩碟失效——P 還是 XOR,但 Q 是「每個資料乘以生成元的不同冪次再 XOR」,運算在 Galois Field GF(2⁸) 上(加法=XOR、乘法要模原始多項式 0x11D,生成元 g={02})。兩個不同的方程式才能解出兩個失效的未知數。GF 乘法雖比 XOR 複雜,但查表/向量化後仍可逐 byte 平行(GPU 亦然)。

為什麼要先學這個(導讀)

P7-T02 你懂了 RAID-5 的 XOR——但它只能容忍一碟(一個 parity = 一個方程式 = 救一個未知數)。這一課進入 RAID-6 的雙 parity,容忍兩碟失效。這是你產品 parity offload 最有價值的部分——因為 Q 的計算量遠大於 XOR。

核心問題:兩碟失效 = 兩個未知數,需要兩個獨立的方程式。RAID-6 用兩個 parity: - P syndrome:還是 XOR(P = D₀ ⊕ D₁ ⊕ …,跟 RAID-5 一樣)。 - Q syndrome:不能也是 XOR(否則兩個方程式一樣,還是解不出兩個未知數)。Q 是「每個資料乘以生成元的不同冪次,再 XOR」:Q = g⁰·D₀ ⊕ g¹·D₁ ⊕ g²·D₂ ⊕ …。

但這個「乘法」不是普通乘法——它在 Galois Field GF(2⁸)(有限體) 上: - 加法 = XOR(就是你已熟悉的)。 - 乘法 = 多項式乘法後模一個原始多項式(複雜,但有查表的快速做法)。

Linux 的 RAID-6 採用:原始多項式 0x11D、生成元 g = {02},可支援至 255 個資料碟。

為什麼這對你是 scope: direct(產品核心數學)?因為 RAID-6 的 Q syndrome 是 GPU offload 最有價值的部分(計算量大於 XOR)。理解其數學,你才能正確實作/驗證 GPU kernel。

重要的資源提醒:這一課的權威是 H. P. Anvin 的「The Mathematics of RAID-6」(含 0x11D、g={02}、還原推導)。若讀 James Plank 的 Reed-Solomon tutorial,務必搭配他的更正稿 CS-03-504——原稿的 information-dispersal matrix 有瑕疵,只讀原稿會學到錯的矩陣。

核心內容

拆成這幾節:(1) 為何 XOR 不夠 → (2) Galois Field GF(2⁸) → (3) GF 的加法(XOR)與乘法 → (4) P 與 Q syndrome → (5) 兩碟失效的還原 → (6) 為何 GF 乘法仍可平行,最後打通關。

1. 為何 XOR 不夠:需要第二個「獨立」的方程式

先理解為什麼 RAID-6 不能用「兩個 XOR parity」。

flowchart TB
    NEED6["要容忍兩碟失效 = 解兩個未知數 → 需兩個『獨立』的方程式"]
    NEED6 --> NAIVE["✗ 笨想法:用兩個 XOR parity?
P1 = D0 ⊕ D1 ⊕ D2
P2 = D0 ⊕ D1 ⊕ D2 ← 一模一樣!"]
    NAIVE --> FAIL3["問題:兩個方程式『相同』
→ 等於只有一個方程式 → 還是解不出兩個未知數
(就像 x+y=5 和 x+y=5,解不出 x、y)"]
    FAIL3 --> SOLUTION3["✓ 解法:第二個 parity 要『不同的權重』
Q = g⁰·D0 ⊕ g¹·D1 ⊕ g²·D2 ⊕ ...
(每個資料乘以生成元 g 的不同冪次 → 每個資料的『係數』不同)
→ P 和 Q 是兩個『線性獨立』的方程式 → 能解兩個未知數"]
    SOLUTION3 --> WHYGF["但這個『乘法』要在 GF(2⁸) 上(第2節)

為何 XOR 不夠:要解兩個未知數,需兩個獨立的方程式。如果兩個 parity 都是 XOR,它們完全相同(P₁ = D₀⊕D₁⊕D₂、P₂ = D₀⊕D₁⊕D₂)——等於只有一個方程式,還是解不出兩個未知數(就像 x+y=5 和 x+y=5 解不出 x、y)。

解法:第二個 parity 要有不同的權重——Q = g⁰·D₀ ⊕ g¹·D₁ ⊕ g²·D₂ ⊕ …,每個資料乘以生成元 g 的不同冪次(所以每個資料的「係數」不同)。這樣 P 和 Q 是兩個線性獨立的方程式,能解兩個未知數。

但這個「乘法」要在 GF(2⁸) 上(第 2 節)——普通整數乘法會溢位(byte 值乘起來超過 255)、且沒有適合的代數性質(無法保證可逆還原)。GF(2⁸) 提供「在 0~255 的 byte 上、有完整加減乘除、且封閉」的運算——這正是 RAID-6 需要的。

2. Galois Field GF(2⁸):byte 上的完整算術

Galois Field(伽羅瓦體 / 有限體)GF(2⁸) 是一套「在 256 個值(一個 byte)上的算術系統」,有加減乘除且封閉。

flowchart TB
    GF["GF(2⁸):256 個元素(剛好一個 byte 的所有值 0~255)"]
    GF --> CLOSED["★ 封閉性:任何兩個元素做運算,結果仍在 0~255 內 ★
(不像普通乘法會溢位超過 255)"]
    GF --> COMPLETE["★ 完整算術:有加、減、乘、除,且每個非零元素有乘法反元素 ★
→ 能做代數(解方程式)→ 能還原失效資料"]
    GF --> REPRESENT["元素的表示:一個 byte 可看成一個『多項式的係數』
例:byte 0b00000101 = x² + 1(每個 bit 是一項的係數)
→ GF 運算 = 多項式運算(但係數在 GF(2),即 mod 2)"]
    NOTE42["為什麼是 2⁸:
① 剛好一個 byte → 對 byte 為單位的儲存完美
② 256 個元素夠多(支援多達 255 個資料碟)"]
    GF --> NOTE42

GF(2⁸) 是「256 個元素(剛好一個 byte 的所有值)上的算術系統」: - 封閉性:任何兩個元素做運算,結果仍在 0~255 內(不像普通乘法會溢位)。 - 完整算術:有加、減、乘、除,每個非零元素有乘法反元素 → 能做代數(解方程式)→ 能還原失效資料。 - 元素的表示:一個 byte 看成一個「多項式的係數」——例如 byte 0b00000101 = x² + 1(每個 bit 是一項係數,係數在 GF(2) 即 mod 2)。所以 GF 運算 = 多項式運算。

為什麼是 2⁸:① 剛好一個 byte → 對 byte 為單位的儲存完美;② 256 個元素夠多(支援多達 255 個資料碟)。

核心(常見誤區:在 GF 上用一般整數乘法/加法):GF 的加法和乘法不是普通的整數運算——加法是 XOR(下節)、乘法是多項式乘法後模一個原始多項式(下節)。用普通整數運算會完全錯。GF(2⁸) 是一個獨立的算術系統,要用它自己的規則。

3. GF 的加法(XOR)與乘法(模 0x11D)

GF(2⁸) 的兩個運算:加法(你已會)和乘法(新的)。

    subgraph add["GF(2⁸) 加法 = XOR(你已熟悉!)"]
        ADD2["a + b = a ⊕ b

→ RAID-6 的 P syndrome 用的就是這個(和 RAID-5 一樣)"]
    end
    subgraph mul["GF(2⁸) 乘法(新的,較複雜)"]

GF(2⁸) 加法 = XOR:a + b = a ⊕ b(你已熟悉!)——RAID-6 的 P syndrome 用的就是這個(和 RAID-5 一樣)。所以你 P7-T02 學的 XOR,已經是 GF 加法。

GF(2⁸) 乘法(較複雜):a × b = (多項式相乘)再模原始多項式。Linux 用原始多項式 0x11D(= x⁸ + x⁴ + x³ + x² + 1)——模它是為了讓結果不超過 8 bit、留在 GF(2⁸) 內。

乘法的快速做法:查表(log/antilog)——用生成元 g={02} 的冪次建一張對數表,把乘法變成「查表 + 加法」:a × b = antilog[ log[a] + log[b] ]。這讓 GF 乘法快、且可向量化(第 6 節 GPU)。

Linux RAID-6 採用:原始多項式 0x11D、生成元 g = {02}(驗收點:說出 Linux RAID-6 使用的原始多項式與生成元)。

常見誤區:用錯原始多項式或生成元——Linux 用 0x11D / g={02},某些教材用別的多項式,算出的 Q 會不相容。要和 kernel 一致,務必用 0x11D / {02}。

(驗收點:實作 GF(2⁸) 乘法(模 0x11D)並驗證若干乘積正確。)

4. P 與 Q syndrome

有了 GF 運算,看 RAID-6 的兩個 parity——P 和 Q syndrome。

flowchart TB
    DATA4["一個 stripe 的資料:D0, D1, D2, ..., D_{n-1}"]
    DATA4 --> P3["P syndrome(和 RAID-5 一樣):
P = D0 ⊕ D1 ⊕ D2 ⊕ ... ⊕ D_{n-1}
(GF 加法 = XOR)"]
    DATA4 --> Q["Q syndrome(RAID-6 新增,用 GF 乘法):
Q = g⁰·D0 ⊕ g¹·D1 ⊕ g²·D2 ⊕ ... ⊕ g^{n-1}·D_{n-1}
(每個資料乘以 g 的不同冪次,再 XOR;g={02})"]

Q:每個資料係數是 g 的不同冪次(g⁰, g¹, g², ...)
→ 兩個方程式的係數不同 → 線性獨立 → 能解兩個未知數"]

    NOTE44["★ 計算量對比 ★

兩個 syndrome(驗收點:對 N 個區塊算出 P 與 Q): - P syndrome(和 RAID-5 一樣):P = D₀ ⊕ D₁ ⊕ … ⊕ D_{n-1}(GF 加法 = XOR)。 - Q syndrome(RAID-6 新增,用 GF 乘法):Q = g⁰·D₀ ⊕ g¹·D₁ ⊕ g²·D₂ ⊕ … ⊕ g^{n-1}·D_{n-1}(每個資料乘以 g 的不同冪次,再 XOR;g={02})。

為何 P、Q 獨立:P 的每個資料係數都是 1(g⁰);Q 的每個資料係數是 g 的不同冪次(g⁰, g¹, g², …)。兩個方程式的係數不同 → 線性獨立 → 能解兩個未知數(這就是第 1 節要的「不同權重」)。

計算量對比(對你產品關鍵):P 只是 XOR(便宜);Q 每個資料要先做 GF 乘法、再 XOR(貴!)。所以 Q 是 GPU offload 最有價值的部分——它計算量大,搬到 GPU 平行算的效益遠高於只算 P。你產品的 parity offload,重頭戲在 Q。

5. 兩碟失效的還原

RAID-6 的容錯魔法:兩碟同時失效,用 P、Q 與其餘資料解出兩個失效的資料。

flowchart TB
    FAIL4["假設 D_i 和 D_j 兩個資料碟同時失效(i ≠ j)
但其餘資料、P、Q 都還在"]
    FAIL4 --> EQUATIONS["列出兩個方程式(把已知的移到一邊):
P 方程:D_i ⊕ D_j = P ⊕ (其餘已知資料的 XOR) = P'
Q 方程:g^i·D_i ⊕ g^j·D_j = Q ⊕ (其餘已知的 g^k·D_k) = Q'"]
    EQUATIONS --> SOLVE2["解這個 GF(2⁸) 上的二元一次聯立:
兩個方程式、兩個未知數(D_i, D_j)
→ 用 GF 的加減乘除(含乘法反元素)解出 D_i 和 D_j
(Anvin 論文有完整推導公式)"]
    SOLVE2 --> RESULT3["還原出 D_i 和 D_j ✓
(因 P、Q 線性獨立,這個聯立必有唯一解)"]
    NOTE45["★ 關鍵:能解,是因為 P、Q 的係數不同(線性獨立)★
若兩個 parity 相同(都 XOR),聯立退化、解不出(第1節)
→ Q 的『不同冪次係數』正是讓兩碟可救的數學基礎"]

兩碟還原(驗收點:模擬兩個資料區塊同時失效,用 P、Q 與其餘區塊還原兩者,逐 byte 比對相符): - 假設 Dᵢ 和 Dⱼ 兩個資料碟失效(其餘資料、P、Q 都在)。 - 列出兩個方程式(已知移到一邊): - P 方程:Dᵢ ⊕ Dⱼ = P ⊕ (其餘已知資料的 XOR) - Q 方程:gⁱ·Dᵢ ⊕ gʲ·Dⱼ = Q ⊕ (其餘已知的 gᵏ·Dₖ) - 解這個 GF(2⁸) 上的二元一次聯立(兩個方程式、兩個未知數)——用 GF 的加減乘除(含乘法反元素)解出 Dᵢ 和 Dⱼ。 - 還原成功(因 P、Q 線性獨立,聯立必有唯一解)。

關鍵:能解,是因為 P、Q 的係數不同(線性獨立)——若兩個 parity 相同(都 XOR),聯立退化、解不出(第 1 節)。Q 的「不同冪次係數」正是讓兩碟可救的數學基礎。

(細節公式在 Anvin 的「The Mathematics of RAID-6」有完整推導;實作時參考它。還有各種失效情形:兩個資料碟、一資料一P、一資料一Q、P+Q——Anvin 都涵蓋。)

6. 為何 GF 乘法仍可平行:GPU 友善

最後,對你產品最重要的:GF 乘法雖比 XOR 複雜,但仍可逐 byte 平行——所以 RAID-6 的 Q 也能 GPU offload。

flowchart TB
    CONCERN["疑慮:GF 乘法比 XOR 複雜(要查表/模多項式)
→ 還能像 XOR 那樣 GPU 平行嗎?"]
    CONCERN --> ANSWER2["✓ 能!因為 Q 也是逐 byte 獨立(像 P,P7-T02)
Q[k] = g⁰·D0[k] ⊕ g¹·D1[k] ⊕ ... (只用各區塊的第 k 個 byte)
→ 每個 byte 位置的 Q 計算,和別的位置無關"]

為何 GF 乘法仍可平行: - Q 也是逐 byte 獨立(像 P,P7-T02):Q[k] = g⁰·D₀[k] ⊕ g¹·D₁[k] ⊕ …——只用各區塊的第 k 個 byte,每個 byte 位置的 Q 計算和別的位置無關。 - GF 乘法的平行做法:① 查表(log/antilog 表)——每個 thread 查表算;② SIMD/向量化——用特殊技巧(如 x86 的 PSHUFB 指令)一次算多個 byte。kernel lib/raid6 就用 SSE2/AVX2 等做(P7-T04)。 - GPU:每個 thread 算一個(或一組)byte 的 GF 乘法 + XOR,查表放 GPU 記憶體,數千 thread 同時算 → Q 的大計算量被 GPU 平行吃掉。

常見誤區:以為 GF 乘法無法平行——查表 + 向量化讓 GF 乘法仍可逐 byte 平行(CPU SIMD、GPU 皆然）。RAID-6 的 Q(計算量大)正是 offload 的重點。

這完成了你的「XOR→parity→GPU 平行」主線的數學部分:RAID-5 的 XOR(P)和 RAID-6 的 GF 乘法(Q)都逐 byte 獨立、都可平行——P 簡單、Q 計算量大但同樣可平行。你產品把這兩者 offload 到 GPU,Q 的效益尤其高。P7-T04 看 kernel 怎麼用 SIMD 加速,P7-T06 看怎麼寫成 GPU kernel。

一句話總結:RAID-6 用兩個 parity（P + Q）容忍兩碟失效——P 是 XOR（係數全 1），Q 是「每個資料乘以生成元 g 的不同冪次再 XOR」（係數不同），運算在 GF(2⁸) 上（加法=XOR、乘法=多項式乘再模原始多項式 0x11D，查表加速；Linux 用 0x11D / g={02}）；P、Q 線性獨立所以能解兩碟失效的 GF 二元聯立；Q 計算量遠大於 XOR，是 GPU offload 最有價值的部分，而它逐 byte 獨立、查表/向量化後仍可平行（CPU SIMD、GPU 皆然）。

常見誤區與踩雷提醒

誤區一:在 GF 上用一般整數乘法/加法。 GF(2⁸) 加法是 XOR、乘法是多項式乘後模原始多項式。用普通整數運算會完全錯。

誤區二:用錯原始多項式或生成元。 Linux RAID-6 用 0x11D / g={02}(與某些教材不同)。要和 kernel 相容,務必用這組。

誤區三:只讀 Plank 原稿未讀更正稿 CS-03-504。 Plank 原稿的 information-dispersal matrix 有瑕疵。讀 Reed-Solomon tutorial 務必搭配 CS-03-504 更正稿(或以 Anvin 的 RAID-6 論文為準)。

誤區四:以為 GF 乘法無法平行。 查表 + SIMD/向量化讓 GF 乘法仍可逐 byte 平行(CPU、GPU 皆然)。RAID-6 的 Q 正是 offload 重點。

動手實作

環境:一般 Linux/編譯環境(數學 + 使用者態 C,安全)。參考 Anvin「The Mathematics of RAID-6」(https://www.kernel.org/pub/linux/kernel/people/hpa/raid6.pdf ）。

任務 A — 實作 GF(2⁸) 乘法(驗收點,核心) 用 C 實作 GF(2⁸) 乘法(模 0x11D)——可用「逐 bit 的 Russian peasant 算法」或「log/antilog 查表」。驗證若干乘積正確(可對照已知值,或驗證代數性質如 a × 1 = a、結合律)。驗收:實作 GF(2⁸) 乘法(模 0x11D)並驗證若干乘積正確。

任務 B — 算 P 與 Q(驗收點) 對 N 個等長區塊,算出 P(XOR)和 Q(Q = ⊕ gⁱ·Dᵢ,用任務 A 的 GF 乘法,g={02})。驗收:對 N 個區塊算出 P 與 Q。

任務 C — 兩碟失效還原(驗收點,核心) 模擬兩個資料區塊同時失效,用 P、Q 與其餘區塊,解 GF 二元聯立還原兩者,逐 byte 比對與原始相符。驗收:模擬兩個資料區塊同時失效,用 P、Q 與其餘區塊還原兩者並逐 byte 比對相符。(參考 Anvin 論文的還原公式。)

任務 D — 說出 Linux 的多項式與生成元(驗收點) 驗收:說出 Linux RAID-6 使用的原始多項式(0x11D)與生成元(g={02})。

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 實作 GF(2⁸) 乘法(模 0x11D)並驗證若干乘積正確。 2. ☐ 對 N 個區塊算出 P 與 Q。 3. ☐ 模擬兩個資料區塊同時失效,用 P、Q 與其餘區塊還原兩者並逐 byte 比對相符。 4. ☐ 說出 Linux RAID-6 使用的原始多項式與生成元。

評分量表: - 60(及格):能算 P/Q 並理解概念。 - 80(熟練):能實作 GF 乘法並還原雙碟失效。 - 100(精通):能完整推導兩碟救援並解釋 GF 乘法的平行化(對應 GPU)。

延伸與銜接

  • 對應工作場景:直接對應(產品核心數學)——RAID-6 的 Q syndrome 是 GPU offload 最有價值的部分(計算量大於 XOR);理解其數學才能正確實作/驗證 GPU kernel。

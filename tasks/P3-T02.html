P3-T02 · 從原始碼編譯與設定 kernel(Kconfig / menuconfig / make)

一句話:kernel 有上萬個可開關的功能,記錄在 .config 裡;每個功能可選「編進核心(=y)、編成可載入模組(=m)、或不編(=n)」。學會用 Kconfig 調整、make 編譯,你才能為自己產品的 module 配好相依的 kernel 選項(如 P2PDMA、IOMMU、NVMe)。

為什麼要先學這個(導讀)

P1-T11 你已經編過一次 kernel、在 QEMU 開機、接過 GDB。那一課的重點是「打通整條鏈」。這一課回到其中設定與編譯的環節,把它學深——因為配置 kernel 是你日後天天要做的事。

核心是 Kconfig 系統:kernel 有上萬個可開關的功能選項(支援哪些硬體、哪些檔案系統、哪些特性),這些開關記錄在一個叫 .config 的檔案裡。而每個功能有三種狀態,這是這一課最重要的概念: - =y:編進核心映像(built-in,開機就在)。 - =m:編成可載入模組(LKM,需要時才 modprobe 載入)。 - =n:不編(這個功能不存在於這個 kernel)。

為什麼這對你是 scope: direct?因為你產品的 module 需要特定的 kernel 選項開啟才能運作。例如: - P2PDMA(PCIe peer-to-peer DMA,讓 NVMe 直接和 GPU 傳資料——你產品的核心)需要 CONFIG_PCI_P2PDMA=y。 - IOMMU(影響 DMA 的位址轉換,P6)有對應的設定。 - NVMe 驅動本身是個選項(=y 或 =m)。

如果你不懂 Kconfig,就配不出能跑你產品的 kernel——你會遇到「我的 module 用的功能 kernel 沒開」這種問題。這一課讓你掌握配置產品執行環境的基礎。

開始之前(前置確認)

  • 依賴:P3-T01(kernel 架構與目錄)、P1-T11(你已建好 QEMU 環境、編過一次 kernel)。
  • 自我檢測: 1. 你還記得 P1-T11 的 make defconfig、CONFIG_DEBUG_INFO、vmlinux/bzImage 嗎?這課深入這些。 2. 你還記得 P0-T08 的 #ifdef 條件編譯嗎?.config 的 =y/=n 本質就是大規模的條件編譯開關。
  • 環境:你的開發主機(編譯)+ QEMU(驗證)。編譯本身與在 QEMU 驗證都不碰你的主機核心。

核心內容

拆成這幾節:(1) Kconfig 與 .config → (2) 三種狀態 =y/=m/=n → (3) 設定的入口:defconfig/menuconfig/olddefconfig → (4) 編譯與產出 → (5) 安裝模組與映像 → (6) 為你的產品配選項,最後打通關。

1. Kconfig 與 .config:設定的真相來源

kernel 的可設定選項由 Kconfig 系統管理。每個選項有個名字(CONFIG_XXX),它們的值集中記錄在原始碼樹根目錄的 .config 檔案裡。

flowchart TB
    KCONFIG["Kconfig 檔案(散布在各目錄)
定義有哪些選項、選項的說明、
選項之間的相依關係"]
    CONFIG[".config(原始碼樹根)
記錄每個選項的當前值
CONFIG_NVME=m
CONFIG_PCI_P2PDMA=y
CONFIG_XXX=n ..."]
    BUILD["編譯時:Kbuild 讀 .config,
決定編譯哪些程式碼、
每段編成什麼(built-in/模組/不編)"]
    KCONFIG --> CONFIG --> BUILD
    style CONFIG fill:#e8a33d,color:#10100e
    style BUILD fill:#8a9a5b,color:#10100e

.config 本質上是一大堆 CONFIG_XXX=y/m/n 的開關(回顧 P1-T11)。它是整個 build 的「設定真相來源」——編譯時,Kbuild 讀它來決定「編哪些程式碼、每段編成什麼」。這正是 P0-T08 條件編譯的大規模應用:kernel 程式碼裡滿是 #ifdef CONFIG_XXX,.config 的值決定哪些程式碼被包含進這次編譯。

Kconfig 還處理相依關係:有些選項依賴別的選項(例如某功能需要先開另一個)。當你開一個選項,Kconfig 會提示或自動處理它的相依。

2. 三種狀態:=y(內建)vs =m(模組)vs =n(不編)

這是這一課最核心的概念。每個功能選項可以是三種狀態之一,差別在「編不編、以及編成什麼形式」:

flowchart TB
    OPTION["一個功能選項(如 NVMe 驅動)"]
    OPTION --> Y["=y(built-in 內建)
編進核心映像 vmlinux/bzImage
→ 開機時就載入、一直在
→ 不能卸載"]
    OPTION --> M["=m(module 模組)
編成獨立的 .ko 檔(LKM)
→ 需要時才 modprobe/insmod 載入
→ 可卸載(rmmod)、可傳參數"]
    OPTION --> N["=n(不編)
這個功能完全不編進來
→ 這個 kernel 沒有這個功能"]
    style Y fill:#6fa8b8,color:#10100e
    style M fill:#e8a33d,color:#10100e
    style N fill:#c2603a,color:#f4ecd8

三者的實際差異: - =y:功能編進核心映像,開機就在、不能卸載。適合「一定要有、核心啟動就需要」的功能(例如開機要用的根檔案系統驅動)。 - =m:功能編成獨立的 .ko 模組檔,不在核心映像裡,要用 modprobe/insmod 才載入。適合「不一定要有、或想動態管理」的功能。你自己寫的 module 天生就是這種(out-of-tree 模組,P3-T03)。 - =n:不編。這個 kernel 裡沒有這個功能。

驗證差異的方法:=m 的功能,開機後用 lsmod 看得到(載入後)、可以 modprobe 載入/rmmod 卸載;=y 的功能直接在核心裡,lsmod 看不到它(因為它不是模組)。這個區別你會在動手實作裡親眼驗證。

跟你產品的關聯:你日後可能把產品的某些功能編成 =m(方便開發、更新),某些依賴的 kernel 功能設成 =y(確保一定在)。理解三態,你才能做這些決定。

3. 設定的入口:defconfig / menuconfig / olddefconfig

你不會手動編輯 .config(上萬行)。kernel 提供幾個 make 目標來產生/修改它:

flowchart TB
    subgraph targets["產生/修改 .config 的主要方式"]
        DEFCONFIG["make defconfig
產生一個合理的預設 .config
(針對你的架構,如 x86-64)
→ 通常從這裡起步"]
        MENUCONFIG["make menuconfig
文字選單介面,
逐項瀏覽/開關選項
(有搜尋、有選項說明)"]
        OLDDEFCONFIG["make olddefconfig
基於現有 .config,
把『沒設定的新選項』補上預設值
(改了 .config 或換版本後用)"]
    end
    style DEFCONFIG fill:#6fa8b8,color:#10100e
    style MENUCONFIG fill:#e8a33d,color:#10100e
    style OLDDEFCONFIG fill:#8a9a5b,color:#10100e

  • make defconfig:產生一份合理的預設設定(回顧 P1-T11 你用過)。起步點。
  • make menuconfig:開一個文字選單介面,讓你逐項瀏覽、搜尋、開關選項——每個選項有說明,還顯示相依關係。這是手動調整的主要工具。defconfig 和 menuconfig 的差別(驗收點):前者是「一鍵產生預設」,後者是「互動式逐項調整」。
  • make olddefconfig:當你改了 .config、或換了 kernel 版本,有些「新選項」還沒設定值——這個指令把它們補上預設值,避免編譯時被一堆問題卡住(常見誤區:改了 .config 卻沒補預設,導致編譯中斷或行為怪異)。

4. 編譯與產出:make 與兩個產物

設定好 .config,就編譯(回顧 P1-T11,這裡複習要點):

flowchart LR
    MAKE["make -j$(nproc)
(用所有核心平行編譯)"]
    KBUILD["Kbuild 依 .config 編譯:
=y 的編進映像,=m 的編成 .ko"]
    OUTPUT["產出兩類:
① vmlinux/bzImage(核心映像,含所有 =y)
② 各個 .ko 模組檔(所有 =m)"]
    MAKE --> KBUILD --> OUTPUT
    NOTE["記得 CONFIG_DEBUG_INFO=y(P1-T11):
編入除錯符號,後續 gdb/KASAN 需要"]
    OUTPUT --> NOTE
    style KBUILD fill:#e8a33d,color:#10100e
    style NOTE fill:#6fa8b8,color:#10100e

編譯產出兩類東西:核心映像(vmlinux/bzImage,包含所有 =y 的功能)和模組檔(各個 .ko,對應所有 =m 的功能)。

把「同一份 .config 如何決定每段程式碼的去向」畫成一張流動圖:

flowchart TB
    CONFIG2[".config(=y / =m / =n)"]
    CONFIG2 --> KBUILD2["make:Kbuild 依每個選項的值分流"]
    KBUILD2 --> YBRANCH["=y 的程式碼 → 編進核心映像"]
    KBUILD2 --> MBRANCH["=m 的程式碼 → 各自編成 .ko"]
    KBUILD2 --> NBRANCH["=n 的程式碼 → 根本不編(#ifdef 排除,P0-T08)"]
    YBRANCH --> VMLINUX["vmlinux / bzImage(含所有 =y)"]
    MBRANCH --> KOS["一堆 .ko 模組檔(所有 =m)"]
    VMLINUX --> BOOT2["QEMU 用 bzImage 開機"]
    KOS --> INSTALL2["modules_install → /lib/modules,modprobe 載入"]
    style CONFIG2 fill:#e8a33d,color:#10100e
    style VMLINUX fill:#6fa8b8,color:#10100e
    style KOS fill:#8a9a5b,color:#10100e

幾個要點(部分回顧 P1-T11): - 用 make -j$(nproc) 平行編譯加速。 - 記得開 CONFIG_DEBUG_INFO(常見誤區:忘了它,後續 P3-T13/P3-T14 的 gdb/KASAN 就沒符號)。 - 別把所有東西都編成 =y(常見誤區):映像會過大、編譯過久。只把必要的設 =y,其餘該 =m 或 =n。

5. 安裝模組與映像

編好之後,模組和映像要「安裝」到對的位置,系統才找得到:

flowchart TB
    subgraph install["安裝"]
        MODINSTALL["make modules_install
把編好的 .ko 模組
裝到 /lib/modules/<版本>/
→ modprobe 才找得到"]
        IMGINSTALL["make install(或手動複製)
把核心映像裝到開機位置
(QEMU 場景:直接用 bzImage 路徑啟動,P1-T11)"]
    end
    DEPMOD["depmod:
計算模組間的相依關係
(modules_install 通常會自動跑)
→ modprobe 靠它解析相依"]
    MODINSTALL --> DEPMOD
    style MODINSTALL fill:#e8a33d,color:#10100e
    style DEPMOD fill:#8a9a5b,color:#10100e

  • make modules_install:把 .ko 模組裝到 /lib/modules/<版本>/,這樣 modprobe 才找得到它們。它通常會自動跑 depmod(計算模組間相依,modprobe 靠它知道「載入 A 前要先載 B」——這個相依機制 P3-T04 會深入)。
  • make install:把核心映像裝到開機位置。(在 QEMU 學習場景,你常直接用 bzImage 的路徑啟動,不必正式安裝——回顧 P1-T11。)

在你的 QEMU 開發循環裡,通常是「編譯 → 用 bzImage 啟動 QEMU → 在 VM 裡 insmod 你的 module 測試」。modules_install 在「要讓 VM 內的系統能 modprobe 內建模組」時用。

6. 為你的產品配選項:P2PDMA、IOMMU、NVMe

這是這一課對你最關鍵的應用。你產品依賴一些特定的 kernel 選項,要在 .config 裡開對:

flowchart TB
    subgraph yourconfig["你產品相關的關鍵選項(示意)"]
        NVME["CONFIG_NVME_CORE / CONFIG_BLK_DEV_NVME
= NVMe 驅動
(=y 或 =m,跟你的 NVMe SSD 溝通)"]
        P2P["CONFIG_PCI_P2PDMA=y
= PCIe peer-to-peer DMA
(讓 NVMe 直接和 GPU 傳資料,你產品核心,P6/P7)"]
        IOMMU["IOMMU 相關選項
(影響 DMA 位址轉換,P6)"]
        DEBUG["CONFIG_DEBUG_INFO=y +
後續 KASAN/lockdep 等 debug 選項
(開發期用,P3-T13/T14)"]
    end
    NOTE["配置原則:
① 開啟產品功能需要的選項
② 注意選項的相依(Kconfig 會提示)
③ 缺 QEMU 對應的 virtio/檔案系統選項會開不了機(P1-T11 誤區)"]
    yourconfig --> NOTE
    style P2P fill:#e8a33d,color:#10100e
    style NOTE fill:#8a9a5b,color:#10100e

實際配置時: - NVMe 驅動:CONFIG_BLK_DEV_NVME 等,設 =y 或 =m(看你要內建還是模組)。 - P2PDMA:CONFIG_PCI_P2PDMA=y——這是讓 NVMe 直接和 GPU 傳資料的關鍵(你產品的核心能力,P6/P7 會深入)。注意(這是當初 spec 標記要驗證的版本敏感點):P2PDMA 對 NVMe 的支援有條件(例如與 RAID0/multipath、KASLR 的互動限制),這些到 P6 會詳查。 - IOMMU 相關:影響 DMA 的位址轉換(P6)。 - 開發期 debug 選項:CONFIG_DEBUG_INFO、後續的 KASAN/lockdep(P3-T13/P3-T14)。

配置時要注意相依(Kconfig 會提示)和別漏 QEMU 需要的選項(virtio 裝置、檔案系統——漏了會開不了機,回顧 P1-T11 誤區)。你現在有能力為產品配出一個能跑的 kernel 環境。

一句話總結:kernel 的上萬功能由 Kconfig 管理、記在 .config,每個功能可選 =y(內建)、=m(模組)、=n(不編);用 defconfig/menuconfig/olddefconfig 設定、make 編譯產出映像與 .ko、modules_install 安裝;掌握這套,你才能為產品開對選項(NVMe、P2PDMA、IOMMU、debug),配出能跑你 module 的 kernel 環境。

常見誤區與踩雷提醒

誤區一:改了 .config 卻沒重編相依項。 改動後用 make olddefconfig 把新選項補上預設值,避免編譯中斷或行為怪異。

誤區二:缺少 QEMU 對應的 virtio/檔案系統選項導致開不了機。 確認虛擬裝置驅動與所需檔案系統有編進去(回顧 P1-T11)。

誤區三:把所有東西都編成 =y。 映像過大、編譯過久。只把必要的設 =y,其餘 =m 或 =n。

誤區四:忘記 CONFIG_DEBUG_INFO。 後續 P3-T13/P3-T14 的 gdb/KASAN 需要除錯符號。開發用的 kernel 務必開它。

誤區五:混淆 =y 與 =m 的行為。 =y 編進映像、開機就在、lsmod 看不到、不能卸載;=m 是獨立 .ko、需 modprobe 載入、lsmod 看得到、可卸載。

動手實作

環境:開發主機(編譯)+ QEMU(驗證)。不碰主機核心。

任務 A — 把一個功能從 =y 改成 =m 並驗證(驗收點) 挑一個適合做模組的功能(例如某個檔案系統如 CONFIG_BTRFS_FS,或某個非開機必需的驅動)。用 make menuconfig 把它從 =y 改成 =m(在選單裡找到它,按鍵切換成 M)。重編(make -j$(nproc) + make modules_install)。在 QEMU 開機後: - 用 lsmod 看它(載入後)。 - 用 modprobe <模組名> 載入它。 驗收:該模組能在 QEMU 中被 lsmod 看到並 modprobe。 對比它原本 =y 時 lsmod 看不到(因為內建)。

任務 B — 說明 defconfig vs menuconfig(驗收點) 用一句話說明 make defconfig 和 make menuconfig 的差異。(提示:一鍵預設 vs 互動式逐項調整。)驗收:能說出差異。

任務 C — 編出帶 debug info 的 kernel(驗收點) 確認 .config 裡 CONFIG_DEBUG_INFO=y(用 menuconfig 搜尋,或檢查 .config)。編譯出帶除錯符號的 kernel,供 P3-T13/P3-T14 的 gdb/KASAN 使用。驗收:編出的 kernel 含 debug info(後續能用 gdb 看符號,回顧 P1-T11)。

任務 D — 找你產品的選項 用 make menuconfig 的搜尋功能(按 /),搜尋 P2PDMA、NVME、IOMMU,看看它們在選單的哪裡、目前是什麼狀態、有什麼相依。寫一兩句:CONFIG_PCI_P2PDMA 對你產品為什麼重要?(提示:NVMe↔GPU 直接傳資料。)

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 用 menuconfig 將某模組從 =y 改為 =m,重編後在 QEMU 中以 lsmod 看到它、並可 modprobe。 2. ☐ 說出 make defconfig 與 make menuconfig 的差異。 3. ☐ 編出帶 debug info 的 kernel 供 Phase 3 後續 gdb 使用。

評分量表: - 60(及格):能編出可開機 kernel。 - 80(熟練):能用 Kconfig 調整選項並驗證。 - 100(精通):能解釋 =y/=m/=n 對開機流程與記憶體的影響。

延伸與銜接

  • 對應工作場景:直接對應——你需要為自家 module 設定相依的 kernel 選項(P2PDMA、IOMMU、NVMe);理解 Kconfig 才能正確配置產品執行環境。
  • 這課餵給未來的:=m 的概念 → P3-T03 你寫的 out-of-tree module;depmod/模組相依 → P3-T04;debug 選項 → P3-T13/P3-T14;P2PDMA/IOMMU 選項 → P6 DMA。
  • 下一步 → P3-T03 第一個 Loadable Kernel Module:你已經會設定、編譯 kernel,也理解了 =m(模組)的概念。下一課終於要親手寫你的第一個 kernel module!從一個 hello-world 開始:module_init/module_exit、out-of-tree 的 Makefile、用 printk 跟核心溝通、insmod/rmmod 載入卸載。這就是你公司產品的核心交付物形式——你日後所有 kernel 工作都從這個骨架開始。(再次提醒:module 只在 QEMU 裡測試!)

P0-T02 · 指標基礎與位址思維

一句話:學會用「東西放在哪個位址」來思考,而不是只用「變數叫什麼名字」。這是你從高階語言跨進系統世界,要換上的第一副眼鏡——而 kernel 整個世界都用這副眼鏡看事情。

為什麼要先學這個(導讀)

在 PHP 或 JS 裡,你寫 $x = 5,然後用 $x。你從來不問「5 這個值,實際存在記憶體的哪個格子裡?」——因為語言幫你藏起來了。變數對你來說是個名字,名字背後的位址是語言的私事,你碰不到也不需要碰。

C 把這層紗整個掀開。在 C 的世界,每一個變數都住在記憶體裡一個有編號的格子,這個編號叫位址(address)。而指標(pointer),就是「一個專門用來存放位址的變數」。

這聽起來只是「多一層間接」,但它是整個 kernel 世界的母語。為什麼?因為 kernel 的工作,本質上就是在管理記憶體——哪塊記憶體配給哪個行程、這塊 DMA 緩衝區的位址是多少、這個資料結構真正住在哪裡、這個指標指向的東西還有效嗎。kernel 程式碼裡幾乎每一行都在操作指標。

你對指標的掌握程度,幾乎直接決定你之後讀 kernel 原始碼是「看得懂」還是「看天書」。 沒有任何一個 C 概念比指標更值得你花時間練到變成直覺。這一課我們把指標從「可怕的玄學」拆解成「就是個存位址的盒子」,而且每一步都配圖。

開始之前(前置確認)

  • 依賴:P0-T01(你已經能編譯、執行、用 gdb 看一支程式)。
  • 自我檢測: 1. 你能寫一個有變數、會印出變數值的 C 程式並編譯執行嗎? 2. 你知道 printf 裡 %d 是印整數嗎?(這課還會用到 %p,專門印位址) 3. 你還記得 P0-T01 裡「記憶體是一塊一塊有編號的東西」這個畫面嗎?這課從那裡接續。

核心內容

拆成這幾節:(1) 記憶體是有編號的格子 → (2) 位址與指標是什麼 → (3) 兩個運算子 & 和 * → (4) 透過指標改值(指標的威力)→ (5) 指標是有型別的 → (6) 指標運算 p+1 的真相 → (7) NULL 與野指標,最後打通關。

1. 先建立畫面:記憶體是一條有編號的格子

把記憶體想成一條很長的儲物櫃,每個櫃子能放一個 byte(位元組),每個櫃子有一個固定的編號——這個編號就是位址。

當你宣告 int x = 5;,系統會找一塊空櫃子放進去。因為 int 在 64 位元系統上通常佔 4 個 byte,所以它會佔用 4 個連續的櫃子,並把這塊的起始編號(第一個櫃子的位址)記下來,當作「x 在哪裡」。

┌─────┐

從現在起,腦中要常駐這個畫面:每個變數 = 記憶體裡某個位址上的一塊空間。「變數名」只是你(和編譯器)對那個位址的暱稱。

2. 位址與指標:暱稱 vs 門牌號

x 是暱稱,0x1004 是門牌號。大多數時候你用暱稱就夠了。但有些場合,你需要的是門牌號本身——例如你想告訴一個函式「去改動 x」,你不能把暱稱 x 傳過去(函式不認得你的暱稱),你得把門牌號給它,它才找得到。

指標(pointer)就是「一個專門用來存放門牌號(位址)的變數」。

        P["指標變數 p
裡面存『某個位址』(0x1004)
它自己也住在某個位址(比如 0x2000)"]

注意右邊那行小字:指標本身也是個變數,也住在記憶體某個位址裡。它只是「裡面裝的剛好是另一個東西的位址」而已。這點現在記著,第 7 節和未來的「指標的指標」會用到。

3. 兩個運算子:&(取址)與 *(解參考)

操作指標,核心就兩個符號。把它們的「讀法」記死,後面就不會亂:

  • &x 讀作「x 的位址」。它回答:「x 住在哪個門牌號?」
  • *p 讀作「p 指向的那個東西」。如果 p 裡存的是 x 的位址,那 *p 就是 x 本人。這個動作叫解參考(dereference)——「照著門牌號去把門後的東西取出來」。

用一張圖看這兩個動作的方向:

flowchart LR
    X["變數 x = 5
@ 0x1004"]
    P["指標 p = 0x1004
@ 0x2000"]
    X -->|"&x:取出 x 的位址 → 0x1004"| P
    P -->|"*p:照 p 存的位址去取東西 → 5"| X
    style X fill:#8a9a5b,color:#10100e
    style P fill:#6fa8b8,color:#10100e

& 和 * 是一對方向相反的操作:& 從「東西」拿到「它的位址」;* 從「位址」拿回「那個東西」。

把它寫成程式:

int x = 5;
int *p = &x;     // 宣告一個指標 p,把 x 的位址(&x)存進去

int *p 的意思是「p 是一個指標,它指向的東西是 int」。= &x 把 x 的位址放進 p。

4. 透過指標改值:指標真正的威力

前面都還只是「存位址、取東西」。指標真正讓人「啊,原來如此」的時刻,是透過位址去改動那個位址上的資料。

#include <stdio.h>
int main(void) {
    int x = 5;
    int *p = &x;          // p 存了 x 的位址

    printf("x 的值   = %d\n", x);            // 5
    printf("x 的位址 = %p\n", (void*)&x);    // 例如 0x7ffd1234
    printf("p 的內容 = %p\n", (void*)p);     // 和上面一樣!p 存的就是 x 的位址
    printf("*p 的值  = %d\n", *p);           // 5,透過位址找回 x

    *p = 99;              // 關鍵這行:透過 p 指向的位址,把那裡的值改成 99
    printf("現在 x   = %d\n", x);            // 99!x 被 p 改掉了
    return 0;
}

最關鍵的是 *p = 99; 這一行。 你沒有碰 x 這個名字,你碰的是「p 指向的那個位址上的東西」,結果 x 變了。為什麼?因為 p 裡存的就是 x 的位址,*p 就是 x 那塊空間本身。

這就是指標的威力,也是它在 kernel 裡無所不在的原因:你握著一個位址,就能操作那個位址上的資料,不管它原本叫什麼名字、是誰的。 函式之間傳遞與修改大型資料、kernel 操作你傳進去的 buffer,全靠這個。

比喻:&x 像問「小明住哪?」得到「忠孝東路 100 號」。指標 p 就是你手上那張寫著「忠孝東路 100 號」的便條。*p 就是「照著便條上的地址,去敲那扇門,看到門後的那個人(小明)」。而 *p = 99 就是「照著地址去那戶人家,把裡面的東西換成新的」——你動的是那個地址的內容,不是便條。

比喻的極限:地址便條這比喻很好,但別忘了——便條本身也放在某個抽屜裡(指標 p 自己也住在一個位址 &p)。而且便條可以「沒寫地址」或「寫了一個亂七八糟的地址」(NULL 或野指標,第 7 節),這時照著它去敲門就會出事。真實的指標比「一張地址便條」多了這些狀態。

5. 指標是有型別的:int* ≠ char*

這是新手常忽略、但極重要的一點:指標不只存位址,它還記得「我指向的東西是什麼型別」。

  • int *p 知道它指向一個 int(在多數平台佔 4 bytes)。
  • char *q 知道它指向一個 char(佔 1 byte)。
  • double *d 知道它指向一個 double(佔 8 bytes)。

「位址」本身只是一個編號,看起來都一樣(都是個數字)。但指標的型別,決定了兩件事:(a) 解參考時要從那個位址讀幾個 byte、怎麼解讀;(b) 做指標運算時,一步跨多遠(下一節)。

當成一個 int"]
    ADDR -->|"用 char* 解參考"| C["從 0x1000 讀 1 個 byte,
當成一個 char"]
    ADDR -->|"用 double* 解參考"| D["從 0x1000 讀 8 個 byte,

換句話說,型別告訴指標「該怎麼看待它指向的那塊記憶體」。同一個位址,用不同型別的指標去解讀,讀出來的東西可以完全不同。

6. 指標運算:p + 1 的真相(會嚇到你)

來看一個常讓初學者震驚的事實:

int *p = ...;     // 假設 p 現在是 0x1000
p = p + 1;        // p 現在是 0x1004,不是 0x1001!

p + 1 不是「位址數值加 1」,而是「往前跳過一整個它指向的型別」。因為 p 指向 int(4 bytes),所以 p + 1 讓位址實際增加 4。

        direction LR

@0x1000"]
        e1["元素1
@0x1004"]
        e2["元素2
@0x1008"]
    end
    p0["p (= 0x1000)"] -.指向.-> e0
    p1["p+1 (= 0x1004,

    p2["p+2 (= 0x1008)"] -.指向.-> e2
    style e0 fill:#8a9a5b,color:#10100e

對照: - int *p(指向 4-byte int):p + 1 → 位址 +4 - char *q(指向 1-byte char):q + 1 → 位址 +1 - double *d(指向 8-byte double):d + 1 → 位址 +8

這是 C 設計的刻意巧思:它讓你可以把指標當成「陣列的游標」——p + i 自動算出第 i 個元素的位址,你不用自己乘以型別大小。編譯器替你乘了。這也正是為什麼下一課(P0-T03)會說「陣列和指標是親戚」——arr[i] 底層就是 *(arr + i),用的就是這個指標運算。

7. NULL 與野指標:沒寫地址 vs 寫了亂碼

指標有兩種「危險狀態」,要分清楚:

NULL 指標:int *p = NULL;。NULL 是一個特殊值(實務上是位址 0),意思是「這個指標目前不指向任何有效的地方」。它像一張「明確留白的便條」——你看到留白,就知道「還沒填地址,別照著它去敲門」。對 NULL 解參考(*p)會立刻、明確地崩潰(在使用者態是 segfault),這其實是好事:錯誤明顯、好抓。

野指標(wild / dangling pointer):宣告了指標但沒給它有效位址,它裡面是記憶體殘留的隨機舊資料:

int *p;        // p 裡是垃圾值(一個隨機的、可能無意義的位址)
*p = 5;        // 災難:照著一個亂寫的地址,往那裡寫 5

這像「一張寫著亂碼地址的便條」——你照著它去敲門,可能砸到完全無關的別人家。在使用者態通常是 segfault;在 kernel 裡,這可能直接讓整台機器當掉,或更陰險——默默寫壞了別的重要資料,造成時好時壞、極難追查的 bug。

規矩:指標宣告後,要嘛立刻指向一個有效的東西(int *p = &x;),要嘛先設成 NULL,並在使用前檢查它是不是 NULL(if (p != NULL) { ... })。絕不要讓一個指標停留在「野」的狀態就拿去解參考。

打通關:把指標收攏成一個心智模型

指標的所有操作,都圍繞「位址」這一個核心。把這課的零件串起來:

一句話總結這個心智模型:指標讓你從「用名字操作資料」升級到「用位址操作資料」,而位址是 kernel 唯一通用的語言。 接下來整個 Phase 0(陣列、struct、記憶體管理、函式指標)都是這個能力的不同應用。

常見誤區與踩雷提醒

誤區一:對野指標解參考。 宣告了指標卻沒初始化,它裡面是隨機位址,解參考它等於亂砸記憶體。規矩:宣告後立刻指向有效東西,或先設 NULL、用前檢查。

誤區二:混淆「指標的值」和「指標指向的值」。 p 是位址(便條上的地址),*p 是那個地址上的東西(門後的人)。printf("%d", p) 想印整數卻給了個位址(型別也不對),printf("%d", *p) 才是印出指向的整數。剛學時,每次用到指標都問自己:「我現在要的是地址,還是地址上的東西?」

誤區三:以為 p + 1 是位址加 1。 它是「跳過一整個元素」。int* 加 1 跳 4 bytes,double* 加 1 跳 8 bytes。搞錯這個,你走訪陣列就會錯位、讀到垃圾。

誤區四:對 void* 直接做指標運算或解參考。 void* 是「不知道指向什麼型別」的通用指標,因為沒有型別、不知道「一個元素多大」,所以不能直接對它做 +1 或 *(那是未定義行為)。要用它,得先轉型成具體型別(如 (int*))。void* 之後在通用 API(像 qsort、malloc 的回傳)裡會常見,先知道它的限制。

動手實作

環境:Linux 終端機,使用者態,安全,不需 root、不動系統。

任務 A — swap:體會「為什麼非傳指標不可」 寫一個函式交換兩個整數。先寫錯的版本(傳值),親眼看它失敗:

void swap_wrong(int a, int b) {   // 傳值:函式拿到的是副本
    int tmp = a; a = b; b = tmp;  // 只改了副本,外面的 x、y 不變
}

再寫對的版本(傳址):

void swap(int *a, int *b) {
    int tmp = *a;   // 取出 a 指向的值
    *a = *b;        // 把 b 指向的值,寫進 a 指向的地方
    *b = tmp;
}
// 呼叫:swap(&x, &y);  ← 傳「位址」,函式才改得到本尊

在 main 裡對同一組 x、y 分別呼叫兩個版本,印出前後的值。你會看到 swap_wrong 沒效果、swap 有效——親手驗證這件事,你就真正懂了「為什麼要傳指標」:函式拿到副本只能改副本,拿到位址才能改本尊。

任務 B — 觀察位址差,驗證指標運算

int arr[5];
for (int i = 0; i < 5; i++)
    printf("&arr[%d] = %p\n", i, (void*)&arr[i]);

你應該看到每個位址比前一個多 4(因為是 int 陣列,每個 int 佔 4 bytes)。然後用一個指標走訪同一個陣列:int *p = arr; p+1; p+2; ...,印出 (void*)(p+i),確認它和 &arr[i] 一致。

任務 C — 三種狀態的對比(小心執行) 宣告一個 NULL 指標,印出它(%p 會顯示 (nil) 或 0)。不要對它解參考(會崩潰)——這個任務的重點是「認得 NULL 的長相、知道解參考它會崩」。寫一句話:為什麼「會明確崩潰的 NULL」比「默默砸記憶體的野指標」其實更安全?

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 寫出正確的 void swap(int *a, int *b) 並在 main 驗證交換成功;同時能展示傳值版本為何失敗。 2. ☐ 對一個 int arr[5],印出相鄰元素位址差恰為 4(或目標平台的 sizeof(int)),並用指標運算 p+i 驗證得到相同位址。 3. ☐ 能用文字解釋為何 int* p; p+1 位址增加 4(而非 1)。

評分量表: - 60(及格):swap 正確。 - 80(熟練):能解釋指標運算的位移規則,能說清楚「為什麼 swap 一定要傳指標」「指標的值 vs 指向的值」的差別。 - 100(精通):能畫出記憶體位址圖,說明指標如何指向、解參考的讀寫方向、以及型別如何影響解讀與位移。

延伸與銜接

  • 對應工作場景:基礎能力——但這是地基中的地基。kernel 程式碼幾乎全程以指標操作資料結構,讀懂指標才讀得懂 kernel;你傳給 kernel 的 buffer、kernel 回給你的結構,全是位址的傳遞。
  • 這課餵給未來的:指標運算 → P0-T03 陣列與指標的關係;「位址思維」貫穿全系列,直到 P6-T01 你會遇到一個顛覆性的位址——dma_addr_t(那是給裝置看的位址,CPU 不能解參考)。
  • 下一步 → P0-T03 陣列、字串與指標的關係:你已經看到陣列的位址是連續的、指標運算會跳元素。下一課揭露一個 C 的核心真相:「陣列名」在大多數情況下,其實會退化成一個指標。這個「退化」是無數 C bug 的源頭,也是理解 C 字串(和它結尾那個看不見的 \0)的鑰匙。

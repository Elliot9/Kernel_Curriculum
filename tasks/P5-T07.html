P5-T07 · 近期 block/storage 演進(LWN,2023–2025)

一句話:你不只要懂現在的 block/NVMe,還要能追正在發生的演進——atomic block writes(防撕裂寫,6.12/6.13 落地)、computational storage 與 device-initiated I/O(裝置自己發 I/O,與 P2PDMA/GDS 呼應,正是你產品的前沿)、phyr(scatterlist 的潛在後繼)。學會讀 LWN 追 upstream,你才能預判技術走向。

為什麼要先學這個(導讀)

恭喜你通過 P5-T06 的出關門檻——能在 NVMe 驅動原始碼裡追一次 I/O。Phase 5 的最後一課,把視野拉到前沿:近期(2023–2025)block/storage 的重要演進。

為什麼一個「養成課程」要教你讀最新的設計討論?因為: 1. 你的領域正在快速演進——computational storage、device-initiated I/O、P2PDMA 正是你產品(RAID over NVMe + GPU)所在的前沿。追蹤這些,你能預判技術走向、評估對產品架構的機會/風險。 2. kernel 是活的——你學的東西會變。學會「讀 LWN 追 upstream 設計討論」這個技能,比記住任何單一事實都重要。

這一課的幾個主題(每個都是真實、近期的演進): - atomic block writes / torn-write protection(防撕裂寫):讓一次寫「全有或全無」——避免斷電/當機時寫到一半(撕裂寫)。我已查證版本錨點:block layer + NVMe/SCSI 支援在 6.12 合併(RWF_ATOMIC/IOCB_ATOMIC),VFS + EXT4/XFS 檔案系統支援在 6.13(STATX_WRITE_ATOMIC 查詢能力)。 - computational storage 與 device-initiated I/O:裝置不只被動回應,還能自己發起 I/O / 做計算——與 P2PDMA(PCIe 點對點 DMA)、GDS(GPU Direct Storage)呼應,正是你產品的方向。 - phyr:scatterlist 的潛在後繼——一個更好的「描述分散記憶體」的結構(呼應 P5-T02 的 bio_vec/scatter-gather)。 - 怎麼讀 LWN:追蹤 upstream 設計討論的方法(LSFMM 峰會報導等)。

為什麼這對你是 scope: direct?如上——device-initiated I/O / computational storage / P2PDMA 正是你產品所在的前沿,追蹤這些討論能預判技術走向。這也是 P6(DMA/P2PDMA)、P7(GDS/CUDA)的前導。

2. atomic block writes / 防撕裂寫

第一個具體例子:atomic block writes(原子區塊寫入)/ torn-write protection(防撕裂寫)。這是近期一個跨多層的重要演進,而且對你的儲存產品直接相關。

問題:撕裂寫(torn write)——一次大寫入若斷電/當機在「寫到一半」,磁碟上會是「一半舊 + 一半新」的混合,對資料庫等是災難。

解法:atomic write——保證「全有或全無」(全部落盤或完全沒寫),不會出現新舊混合(torn-write protection)。

介面(我已查證的版本錨點): - 應用程式用 pwritev2() 帶 RWF_ATOMIC 旗標(對應 bio 的 REQ_ATOMIC,回顧 P5-T02 的 bi_opf)。 - 用 statx() 帶 STATX_WRITE_ATOMIC 查詢裝置支援的原子寫大小範圍(寫長度須是 2 的次方、在 min/max 之間、對齊——回顧 P0-T04 對齊)。

這對你產品直接相關:儲存系統的資料完整性是核心需求,撕裂寫保護正是你會關心的能力。而它的實作橫跨多層(下一節)——這正是「一個變更貫穿 VFS→block→NVMe」的好例子。

3. 一個變更貫穿多層:atomic writes 的落地

atomic writes 是個絕佳的範例,展示一個 storage 變更如何橫跨整條堆疊(回顧 P5-T01 的層)。這也是這一課要你體會的核心:storage 變更往往跨多層,只看單層會誤解。

atomic writes 怎麼貫穿各層(驗收要求:正確指出一個變更跨越的層): - VFS 層(6.13):新介面讓 app 請求原子寫;statx 擴充查詢能力。 - 檔案系統層(EXT4/XFS,6.13):確保檔案的實體 extent 對齊裝置的原子寫邊界(避免原子寫跨邊界而失去保證)。 - block layer(6.12):bio 帶 REQ_ATOMIC;確保 bio 不被拆分到違反原子性(回顧 P5-T02 的 bio 拆分)。 - NVMe/SCSI 驅動(6.12):把原子寫對應到裝置能力(NVMe namespace 可定義原子邊界)。 - 裝置:硬體保證原子落盤。

這是這一課最重要的方法論教訓(常見誤區:忽略一個 storage 變更往往跨多層):你看一個 storage 新功能,不能只看單層——要追它在 VFS、檔案系統、block layer、驅動、裝置各層做了什麼。只看 block layer 的部分,你會誤解整個功能。讀 LWN 報導時,注意它怎麼描述「這個變更動到哪幾層」。

4. computational storage 與 device-initiated I/O

第二組演進,最貼近你產品的前沿:computational storage(計算型儲存) 和 device-initiated I/O(裝置發起的 I/O)。

    NEW2 --> COMP["computational storage:

兩個方向: - computational storage:把計算搬到靠近資料的地方(裝置或其附近),不必把所有資料搬到 CPU 才處理。例如在儲存端做篩選、壓縮——甚至(對你的領域)思考 parity 計算能否更靠近資料。 - device-initiated I/O:裝置自己發起 I/O,不必每次都等 host 下命令。這與 P2PDMA 呼應。

P2PDMA(PCIe 點對點 DMA)是對你產品最關鍵的(驗收要求:說明該變更與你產品是否相關及如何相關):它讓一個 PCIe 裝置直接和另一個 PCIe 裝置傳資料,不經過 host 記憶體(P6 會深入)。這正是你產品的核心——讓 NVMe 直接和 GPU 傳資料(NVMe 的 queue I/O 直接餵給 GPU 算 parity),不必繞道 host 記憶體(省一次複製、降延遲)。GDS(GPU Direct Storage) 就是這個方向的具體技術(P7 會碰)。

所以這組演進不是學術前沿,是你產品的技術基礎。追蹤 LSFMM(Linux 儲存峰會)對 P2PDMA、device-initiated I/O 的討論,你能預判「NVMe↔GPU 直通」這條路的 upstream 進展與限制——直接影響你的產品架構。

把 P2PDMA 對你產品的價值,用「繞道 host vs 直通」的對比畫清楚:

讀 LWN 追 upstream 的方法: - 注意日期與版本(常見誤區:不分版本套用)——一篇 2023 的文章講的功能,可能還沒合併、或已經變樣。看文章日期,對照它講的是哪個 kernel 版本/階段。 - 分辨「設計討論」vs「已合併」——LSFMM(Linux Storage, Filesystem, MM Summit)報導多是討論(還在發展);要知道「已合併」得看 merge window 的報導。別把設計討論當定案 API(這課反覆強調)。 - 追一個主題的時間線——同一主題常有系列文章(提案 → 討論 → 修訂 → 合併),追時間線你才看到全貌。 - 看「跨哪些層、誰在推、有什麼爭議」——理解動機與權衡,不只看結論。

產出(這課的動手任務):選一篇 LWN 文章,寫一頁摘要——問題是什麼、動到哪些層(VFS/block/NVMe)、現況/版本、對你產品的影響。這個「讀一篇深度報導 → 提煉成對產品有意義的摘要」的能力,是你日後持續追蹤領域的工作方式。

一句話總結:你的領域正快速演進,追 upstream 是職業技能——atomic writes/防撕裂寫(6.12 block+NVMe、6.13 VFS+ext4/xfs)示範了一個變更如何貫穿 VFS→block→NVMe;computational storage 與 device-initiated I/O(尤其 P2PDMA:NVMe↔GPU 直通不經 host)正是你產品的前沿;phyr 是 scatterlist 的潛在後繼(尚在討論)。讀 LWN 時注意日期/版本、分辨討論 vs 已合併、追主題時間線——別把報導當定案 API、別只看單層。

常見誤區與踩雷提醒

誤區一:把 LWN 報導當成最終 API。 LSFMM 等報導多是設計討論(仍可能變動)。phyr 就是例子——還在討論、未定案。分辨「討論」vs「已合併」。

誤區二:忽略一個 storage 變更往往跨多層。 atomic writes 橫跨 VFS/檔案系統/block/驅動/裝置。只看單層會誤解整個功能。追它在各層做了什麼。

誤區三:不分版本套用。 注意文章日期與對應 kernel 版本。一篇舊文章講的可能還沒合併、或已變樣。對照版本(如 atomic writes 6.12/6.13)。

動手實作

環境:閱讀 LWN(安全)+ 可選在有支援的 kernel 上試 atomic write(只在 VM)。

任務 A — 讀一篇 LWN 並寫一頁摘要(驗收點,核心) 從指定資源選一篇 LWN 文章(建議從對你產品最相關的選): - Peer-to-peer DMA(LSFMM 2023):https://lwn.net/Articles/931668/ - Device-initiated I/O(LSFMM 2025):https://lwn.net/Articles/1022718/ - Computational storage(LSFMM 2023):https://lwn.net/Articles/931949/ - phyr(scatterlist 後繼):https://lwn.net/Articles/931943/ 寫一頁摘要,正確指出:① 這個變更/討論解決什麼問題;② 動到/跨越哪些層(VFS/block/NVMe);③ 現況與對應版本(或「仍在討論」)。驗收:對選定文章產出一頁摘要,正確指出問題、跨越的層、與現況/版本。

任務 B — 評估對你產品的影響(驗收點,核心) 針對你選的文章,寫一段話:這個變更與你的產品(RAID over NVMe + GPU)是否相關?如何相關?(提示:P2PDMA/device-initiated I/O 高度相關——NVMe↔GPU 直通;atomic writes 與資料完整性相關;phyr 與你的 scatter-gather 資料路徑相關。)驗收:說明該變更與你產品是否相關及如何相關。

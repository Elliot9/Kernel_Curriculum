P1-T05 · 行程 vs 執行緒

一句話:行程是「擁有獨立位址空間的資源容器」,執行緒是「共享那個位址空間的排程單位」。差別的關鍵不在「輕重」,而在是否共享記憶體——而這一點,直接決定了你產品裡哪些地方需要加鎖。

為什麼要先學這個(導讀)

這是你親口列出的核心缺口之一,而它的混淆會直接導致並行 bug。

很多人對 process(行程)和 thread(執行緒)的理解停在「thread 比較輕、process 比較重」。這個說法不算錯,但抓錯了重點。真正的關鍵差異是:行程之間不共享記憶體(各有獨立的虛擬位址空間),而同一行程內的多個執行緒共享記憶體(共用同一個位址空間)。

這個區別建立在上一課 P1-T04 的虛擬記憶體上:每個行程有自己的分頁表、自己的虛擬位址空間,所以行程 A 的指標在行程 B 裡毫無意義、踩不到 B 的資料(隔離)。但同一行程內的執行緒,共用同一份分頁表、同一個位址空間,所以它們能直接讀寫同一塊記憶體——這既是執行緒強大之處(輕鬆共享資料),也是危險之處(共享就可能 race,見 P1-T08)。

為什麼這對你是 scope: direct?因為: - 你的 user space app 是多執行緒的——多個執行緒共享記憶體並行處理 I/O 與 parity。理解「它們共享什麼」決定了你哪裡必須同步。 - kernel 內部也有執行緒(kthread)。 - 「哪裡需要加鎖」這個貫穿你整個並行設計的問題,答案的起點就是「這些執行單位有沒有共享記憶體」。

開始之前(前置確認)

  • 依賴:P1-T04(你已懂每個行程有自己的虛擬位址空間)。這一課完全建立在此之上。
  • 自我檢測: 1. 你能用一句話說明「為什麼行程 A 的指標在行程 B 裡無意義」嗎?(各有獨立位址空間,同一虛擬位址映到不同實體記憶體。) 2. 你寫過多執行緒程式(pthread)嗎?這課要對比 fork(造行程)和 pthread(造執行緒)。

核心內容

拆成這幾節:(1) 行程是什麼:資源容器 → (2) 執行緒是什麼:排程單位 → (3) 共享 vs 不共享(關鍵對照)→ (4) fork:複製出一個行程(與 COW)→ (5) exec:換掉行程的內容 → (6) Linux 的統一觀點:thread 其實是共享資源的 task,最後打通關。

1. 行程(process):一個資源容器

一個行程,是「一支執行中的程式」加上它擁有的所有資源。最核心的資源是它的虛擬位址空間(回顧 P1-T04),此外還有開啟的檔案、各種 OS 資源等。

(自己的 text/data/heap/stack,

        FILES["開啟的檔案

    style FILES fill:#6fa8b8,color:#10100e

關鍵特性:行程之間是隔離的。行程 A 看不到也碰不到行程 B 的記憶體(因為各有獨立位址空間)。這是 P1-T04 虛擬記憶體帶來的隔離——一支行程崩潰,不會搞壞別的行程。

比喻:行程像一間獨立的公寓,有自己的門牌、自己的家具、自己的鑰匙。你在你家做什麼,不會直接影響隔壁那戶——牆壁(位址空間隔離)把你們分開。

2. 執行緒(thread):一個排程單位

一個執行緒,是「CPU 排程的最小單位」——也就是 P1-T01 那個「取指-解碼-執行」迴圈實際在跑的東西。一個行程裡可以有多個執行緒,它們共享這個行程的位址空間和資源,但各自有獨立的執行狀態。

每個執行緒獨立擁有的,主要是「執行所需的私有狀態」:

所以一個執行緒私有的東西很少:主要是它自己的 stack(每個執行緒一個獨立的呼叫堆疊,因為它們各自呼叫各自的函式)和暫存器/PC 狀態(各自執行到不同地方)。其餘——程式碼、全域變數、heap、開啟的檔案——全部共享。

比喻:如果行程是一間公寓,執行緒就像「住在同一間公寓裡的室友」。他們共用客廳、廚房、冰箱(共享的位址空間和資源),但各自有自己的房間和私人行程(私有的 stack 和執行狀態)。

3. 共享 vs 不共享:最關鍵的一張對照

把行程與執行緒的差異,濃縮成這張對照——這是整課的核心,也是你判斷「哪裡要加鎖」的依據:

    subgraph procs["兩個不同行程"]
        direction LR
        PA["行程 A
位址空間 A"]
        PB["行程 B
位址空間 B"]
        PA -.“互不可見,隔離”.- PB
    end
    subgraph thrs["同一行程的兩個執行緒"]
        direction LR
        TA["執行緒 1"]
        TB["執行緒 2"]

    style PB fill:#8a9a5b,color:#10100e
    style TA fill:#e8a33d,color:#10100e

行程之間 同一行程的執行緒之間
位址空間 獨立(各有分頁表) 共享(同一份)
全域變數 各自一份,互不影響 同一份,改了對方看得到
heap 各自的 共享
一方修改記憶體 另一方看不到 另一方直接看到
建立/切換成本 較高(要建整個位址空間) 較低(共用位址空間)
需要同步嗎? 通常不必(沒共享) 必須(有共享就有 race)

最後一列是這課的實用結論:執行緒共享記憶體,所以多執行緒同時讀寫同一個變數,就會發生 race condition(P1-T08),必須加鎖(P1-T09)。行程之間沒共享,通常不需要這層擔心(它們要通訊得透過特別的 IPC 機制)。你產品的多執行緒 app,凡是執行緒間共享的狀態,都是必須同步的點。

4. fork:複製出一個行程(以及 copy-on-write 的真相)

在 Linux/Unix,建立新行程的經典方式是 fork()。它的行為很特別:複製出一個幾乎一模一樣的子行程——子行程得到父行程位址空間的一份「副本」。

    PARENT["父行程
(global = 5, heap 上有資料)"]
    PARENT -->|"fork()"| RESULT
    subgraph RESULT["fork 之後:兩個獨立行程"]
        direction LR
        P["父行程
global = 5"]
        C["子行程
global = 5(自己的副本)"]
    end
    NOTE["fork 回傳值區分父子:
父行程收到子行程的 PID(>0)
子行程收到 0"]
    RESULT --> NOTE
    style P fill:#8a9a5b,color:#10100e
    style C fill:#6fa8b8,color:#10100e

關鍵:子行程的位址空間是獨立的副本。父行程改 global,子行程的 global 不變(反之亦然)——因為它們是兩個行程,各有位址空間。這和執行緒完全相反(執行緒共享,fork 出的行程不共享)。

但這裡有個重要的效率細節:copy-on-write(寫時複製,COW)。 如果 fork 真的把整個位址空間立刻完整複製一份,會很慢且浪費(尤其若子行程馬上要 exec 換掉內容)。所以實際上:

flowchart TB
    S1["fork():不立刻複製記憶體,
父子『共享』同一批實體頁
(但都標記為唯讀)"]
    S2["父或子任一方『讀』:
沒問題,讀共享的頁"]
    S3["父或子任一方『寫』某頁:
觸發 page fault(寫唯讀頁,回顧 P1-T04)"]
    S4["OS 這時才真正複製那一頁,
讓寫的人改自己的副本
(copy-on-write)"]
    S5["結果:只有被改動的頁才真正複製,
沒改的頁繼續共享 → 省時省記憶體"]
    S1 --> S2
    S1 --> S3 --> S4 --> S5
    style S3 fill:#e8a33d,color:#10100e
    style S4 fill:#8a9a5b,color:#10100e

這就是為什麼「fork 後父子共享變數」是個誤解需要澄清:它們邏輯上是各自獨立的副本(一方改不影響另一方),只是底層用 COW 優化,在「真正被寫之前」物理上共享同一份實體頁。對你程式而言,行為就是「各自獨立」;COW 只是 OS 在底下省資源的手段。(注意這裡又用到 P1-T04 的 page fault——寫唯讀頁觸發 fault,OS 才複製。)

5. exec:換掉行程的內容

fork 複製出一個和父行程一樣的子行程,但通常你 fork 是為了讓子行程跑別的程式(例如 shell 執行一個命令)。這就需要 exec 系列函式:把當前行程的內容,整個換成另一支程式。

flowchart LR
    BEFORE["行程(正在跑程式 A)
位址空間裝著 A 的 code/data"]
    EXEC["exec(程式 B)"]
    AFTER["同一個行程(PID 不變)
位址空間整個換成 B 的 code/data
→ 從此開始跑 B"]
    BEFORE --> EXEC --> AFTER
    NOTE["exec 不建立新行程,
而是『換腦』——
同一個行程外殼,換掉裡面跑的程式"]
    style EXEC fill:#e8a33d,color:#10100e
    style AFTER fill:#8a9a5b,color:#10100e

經典組合是 fork + exec:fork 出一個子行程,子行程立刻 exec 換成要跑的新程式。這就是 shell 執行命令的標準模式(fork 一個子行程,exec 成 ls 之類)。這也解釋了為什麼 COW 對 fork 很重要——子行程往往 fork 完馬上 exec,把位址空間整個換掉,如果 fork 時就完整複製,那複製的功就全白費了。

6. Linux 的統一觀點:thread 其實是「共享資源的 task」

最後一個關鍵洞察,會讓前面一切融會貫通。在 Linux kernel 的實作裡,行程和執行緒並沒有兩套完全不同的機制。kernel 內部用一個統一的結構叫 task_struct 來代表「一個可被排程的執行實體」——不管你叫它行程還是執行緒,在 kernel 眼中都是一個 task。

    TASK["kernel 的 task_struct
(一個可排程的執行實體)"]
    TASK --> CASE1["建立新 task 時
『不共享』位址空間等資源
→ 我們稱它為『行程』"]
    TASK --> CASE2["建立新 task 時
『共享』位址空間等資源
→ 我們稱它為『執行緒』"]
    NOTE["差別只在『建立時選擇共享哪些資源』
(底層用 clone() 系統呼叫,
用旗標決定共享位址空間/檔案/信號等與否)
→ 行程 vs 執行緒只是『共享程度』的兩端"]
    CASE1 --> NOTE
    CASE2 --> NOTE
    style TASK fill:#e8a33d,color:#10100e
    style NOTE fill:#8a9a5b,color:#10100e

換句話說:在 Linux,「執行緒」本質上就是「一個和別人共享位址空間(及其他資源)的 task」。行程和執行緒不是兩種不同的東西,而是「同一種東西(task)在『共享多少資源』這個光譜上的兩端」:完全不共享 → 我們叫行程;共享位址空間 → 我們叫執行緒。底層都是 clone() 這個系統呼叫,用旗標決定要共享哪些。

這個統一觀點為什麼重要? 它讓你不再把行程和執行緒當成割裂的兩套概念去背,而是理解成「一個連續光譜」。你日後在 kernel 看到 task_struct、看到 kthread(kernel 裡的執行緒),就知道它們都是 task,差別只在共享什麼。這也呼應你產品:你的多執行緒 app,在 kernel 眼中就是一組共享位址空間的 task。

打通關:把行程與執行緒收攏成一個心智模型

一句話總結:行程與執行緒的本質差異不是「輕重」而是「是否共享位址空間」;行程隔離、執行緒共享,而『共享』正是 race 與加鎖需求的來源;在 Linux 眼中兩者都是 task,只是共享資源的程度不同——記住這個,你就能判斷自己產品裡每一處共享狀態是否需要同步。

常見誤區與踩雷提醒

誤區一:以為行程和執行緒只是「輕重之分」。 關鍵差異是是否共享位址空間(執行緒共享、行程不共享),不只是建立成本。這個區別決定了同步需求。

誤區二:以為 fork 後父子共享變數。 父子是各自獨立的副本(一方改不影響另一方)。底層的 copy-on-write 只是優化(寫前物理共享),邏輯上完全獨立。

誤區三:多執行緒共享全域變數卻不加鎖。 執行緒共享位址空間,多執行緒同時讀寫同一變數會 race(P1-T08),結果不可預測。共享的可變狀態必須同步。

誤區四:以為每個執行緒有自己的全域變數/heap。 不。執行緒只有 stack 和執行狀態是私有的;全域變數、heap、開啟的檔案全部共享。要每執行緒一份,得用特別的機制(thread-local storage)。

動手實作

環境:Linux 終端機,使用者態,安全,不需 root、不動系統。需要 pthread。

任務 A — fork:證明行程位址空間獨立

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int global = 100;
int main(void) {
    pid_t pid = fork();
    if (pid == 0) {              // 子行程
        global += 1;
        printf("子行程:global = %d (PID %d)\n", global, getpid());
    } else {                     // 父行程
        sleep(1);                // 讓子行程先改
        printf("父行程:global = %d (PID %d)\n", global, getpid());
        wait(NULL);
    }
    return 0;
}

觀察:子行程把 global 改成 101,但父行程的 global 仍是 100——證明兩個行程位址空間獨立。寫一句話解釋。

任務 B — pthread:證明執行緒共享記憶體

#include <stdio.h>
#include <pthread.h>
int global = 100;
void *worker(void *_) {
    global += 1;                 // 改的是共享的 global
    printf("執行緒:global = %d\n", global);
    return NULL;
}
int main(void) {
    pthread_t t;
    pthread_create(&t, NULL, worker, NULL);
    pthread_join(t, NULL);       // 等執行緒做完
    printf("主執行緒:global = %d\n", global);   // 會看到 101!
    return 0;
}

觀察:執行緒改了 global,主執行緒也看到變成 101——證明同行程的執行緒共享記憶體。對比任務 A,寫一句話總結兩者的根本差異。

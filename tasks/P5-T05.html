P5-T05 · NVMe 協定基礎(控制器/命名空間、SQ/CQ、doorbell、PRP/SGL)

一句話:NVMe 的核心是「host 在記憶體裡放兩個環狀佇列(提交 SQ、完成 CQ),寫 doorbell 通知裝置去 SQ 取命令,裝置做完寫進 CQ 並翻轉 phase bit」——而資料記憶體位置用 PRP 或 SGL 描述。這條 SQ→doorbell→CQ 流程,正是你產品把 I/O 餵給 GPU 的資料路徑根本。

為什麼要先學這個(導讀)

P5-T04 你掌握了 block layer 端。這一課跨到裝置端的協定——NVMe,你產品的核心。理解 NVMe 怎麼運作,你才懂你產品的資料路徑、以及它的 DMA 行為。

NVMe(NVM Express)是現代 SSD 的標準協定。它設計得極度適合高並行(這就是為什麼它配 blk-mq 能跑百萬 IOPS)。核心模型:

  • 控制器(controller)與命名空間(namespace):一個 NVMe 控制器(那塊 PCIe 裝置,P4-T04)管理一個或多個命名空間(namespace——可看成「邏輯磁碟」,如 /dev/nvme0n1 的 n1)。
  • 提交佇列 SQ 與完成佇列 CQ:NVMe 的核心機制——在 host 記憶體裡放兩個環狀緩衝(ring buffer):SQ(Submission Queue) 放 host 要下的命令、CQ(Completion Queue) 放裝置完成的結果。每核一對 SQ/CQ(對應 blk-mq 硬體佇列,P5-T03)。
  • doorbell(門鈴)暫存器:在 BAR 裡(回收 P4-T04/P3-T11)——host 把命令寫進 SQ 後,寫 doorbell 通知裝置「SQ 有新命令」。
  • 命令與完成項格式:命令是 64-byte、完成項是 16-byte,大小嚴格(回收 P0-T04 對齊)。完成項有個 phase bit,是 host 判斷「這是不是新完成項」的關鍵。
  • PRP 與 SGL:描述「命令的資料在 host 記憶體的哪裡」——PRP(Physical Region Page) 和 SGL(Scatter-Gather List)。這和 P5-T02 的 bio_vec/scatter-gather 呼應,也是 P6 DMA 的關鍵。

為什麼這對你是 scope: direct?因為你產品把 NVMe queue I/O 餵給 GPU——理解 SQ/CQ、doorbell、PRP/SGL,是理解這條資料路徑與其 DMA 行為的根本。你可能要旁路或修改這條路徑,把資料導向 GPU。這一課是 P5-T06(讀 NVMe 驅動原始碼)和 P6(DMA)的基礎。

(我已查證 NVMe 規格現況:Base Spec 2.3 於 2025-08 發布,2.1 是穩定的教學參考。這課教的是穩定的核心機制,不依賴最新版的細節。)

核心內容

拆成這幾節:(1) 控制器與命名空間 → (2) admin queue 與 I/O queue → (3) SQ/CQ:host 記憶體的環狀佇列 → (4) doorbell:通知裝置 → (5) phase bit:判斷新完成項 → (6) PRP 與 SGL:資料在哪,最後打通關。

2. admin queue 與 I/O queue

NVMe 的佇列分兩種用途:admin queue(管理佇列) 和 I/O queue(I/O 佇列)。

兩種佇列: - admin queue:用於控制/管理命令——建立/刪除 I/O 佇列、identify(查裝置資訊)、設定 feature、namespace 管理。裝置初始化時最先用它。只有一對。 - I/O queue:用於實際資料 I/O——read、write。可以多對(每核一對,對應 blk-mq 硬體佇列,P5-T03)。

初始化流程:先有 admin queue → 用它 identify 裝置、建立多個 I/O queue → 之後資料 I/O 走 I/O queue。

常見誤區:混淆 admin queue 與 I/O queue 的用途——admin 管控制/設定(低頻、初始化用),I/O 管實際讀寫(高頻、效能關鍵)。你產品的資料路徑走的是 I/O queue;admin queue 是初始化/管理時用。兩者結構一樣(都是 SQ/CQ,下一節),但用途分明。

3. SQ/CQ:host 記憶體裡的環狀佇列

這是 NVMe 的核心機制。一對佇列 = 一個 SQ(Submission Queue,提交佇列) + 一個 CQ(Completion Queue,完成佇列),都在 host 的記憶體裡,是環狀緩衝(ring buffer)。

    end

SQ/CQ 的運作: - SQ(提交佇列):host 把要下的命令(64-byte) 放進這個環狀佇列。host 寫尾端(tail),裝置從頭端(head)取走執行。 - CQ(完成佇列):裝置把完成結果(16-byte) 放進這個環狀佇列。裝置寫尾端,host 從頭端取走處理。

最關鍵的理解:SQ/CQ 在 host 記憶體裡,不在裝置上。裝置透過 DMA(P6)讀 SQ 的命令、寫 CQ 的完成結果。所以 NVMe 的協作模式是「host 和裝置共享記憶體裡的佇列」——host 放命令進 SQ,裝置 DMA 讀走;裝置把完成寫進 CQ,host 讀走。這個「共享記憶體佇列」的設計,讓 host 和裝置能高效、非同步地協作。

(環狀緩衝就是頭尾指標循環的佇列——回顧資料結構基礎;NVMe 用它讓命令/完成能連續流動。)

4. doorbell:通知裝置

host 把命令放進 SQ 後,裝置怎麼知道「有新命令了」?host 寫 doorbell(門鈴)暫存器通知它——這正是 P3-T11 和 P4-T04 反覆提到的 doorbell。

flowchart TB
    STEP1d["① host 把命令寫進 SQ(host 記憶體)"]
    STEP1d --> BARRIER3["★ 屏障:確保命令已寫好且對裝置可見(P3-T11 命門)★
(dma_wmb——否則裝置讀到還沒寫好的命令 → 資料毀損)"]
    BARRIER3 --> STEP2d["② host 寫 SQ 的 doorbell 暫存器(在 BAR 裡,P4-T04)
writel(新的 tail 值, doorbell 位址)
= 告訴裝置『SQ 的 tail 推進到這,去取新命令』"]
    STEP2d --> STEP3d["③ 裝置看到 doorbell → DMA 讀 SQ 的新命令 → 執行"]
    STEP3d --> STEP4d["④ 執行完 → DMA 寫完成項到 CQ → 發 MSI-X 中斷(P4-T04)通知 host"]
    STEP4d --> STEP5d["⑤ host 處理完成項 → 寫 CQ 的 doorbell(告訴裝置『這些完成項我收了』)"]

    style STEP2d fill:#e8a33d,color:#10100e
    style STEP4d fill:#8a9a5b,color:#10100e

完整的一次 I/O 流程(driver 端): 1. host 把命令寫進 SQ(host 記憶體)。 2. 屏障(回收 P3-T11 的命門!):確保命令已寫好且對裝置可見(dma_wmb)——否則裝置可能讀到還沒寫好的命令,資料毀損。這就是 P3-T11 那條「DMA 描述子必須在按 doorbell 前對裝置可見」規則的具體場景。 3. host 寫 SQ 的 doorbell 暫存器(在 BAR 裡,P4-T04,用 writel)——告訴裝置「SQ tail 推進到這,去取新命令」。 4. 裝置看到 doorbell → DMA 讀 SQ 的新命令 → 執行 → DMA 寫完成項到 CQ → 發 MSI-X 中斷(P4-T04)通知 host。 5. host 處理完成項 → 寫 CQ 的 doorbell(告訴裝置「這些完成項我收了」)。

doorbell 是 host→裝置的通知機制。注意第 2 步的屏障——這是你 P3-T11 學的 DMA 正確性命門,在 NVMe 這裡是真實場景:命令(描述子)必須在按 doorbell 前對裝置可見。對你產品的資料路徑,這個屏障絕不能漏。

5. phase bit:判斷新完成項

一個精巧的設計:host 怎麼知道 CQ 裡「哪些是新的完成項」?CQ 是環狀的、裝置非同步地寫——靠 phase bit(相位位元)。

    PROBLEM5["問題:CQ 是環狀緩衝,裝置非同步寫入

    PROBLEM5 --> PHASE["解法:每個完成項有一個 phase bit(1 bit)
裝置每寫滿一輪 CQ,就翻轉它寫入的 phase 值"]
    PHASE --> HOW4["host 端:記住『當前期望的 phase 值』

② phase bit != 期望值 → 還沒有新的(裝置還沒寫到這)

    HOW4 --> WHY4["好處:不需要額外的『有效旗標』記憶體寫入/清除,

phase bit 機制(常見誤區:忽略 phase bit 是判斷新完成項的關鍵): - 問題:CQ 是環狀的、裝置非同步寫——host 怎麼知道某個 CQ 槽位是「新完成項」還是「上一輪的舊資料」? - 解法:每個完成項有一個 phase bit。裝置每寫滿一輪 CQ,就翻轉它寫入的 phase 值。 - host 端:記住「當前期望的 phase 值」。讀一個 CQ 槽位:phase bit == 期望值 → 新完成項,處理;phase bit != 期望值 → 還沒有新的(裝置還沒寫到這)。每繞 CQ 一圈,host 翻轉自己期望的 phase。

好處:不需要額外的「有效旗標」記憶體操作——單一 bit 就能區分新舊,高效。這是 NVMe 高效協作的一個精巧細節。讀 NVMe 驅動(P5-T06)的完成處理時,你會看到它檢查 phase bit 來判斷有沒有新完成項。

6. PRP 與 SGL:資料在 host 記憶體的哪裡

最後:命令說「讀/寫某段資料」,但那段資料在 host 記憶體的哪裡?裝置要 DMA 存取它,需要知道位置。NVMe 用兩種方式描述:PRP 和 SGL。

兩種描述(驗收點:說明 PRP 與 SGL 的差異與各自用途): - PRP(Physical Region Page):用實體頁位址的列表描述資料位置——假設資料按頁(page)組織。簡單,適合頁對齊的緩衝(回顧 P0-T04 對齊)。 - SGL(Scatter-Gather List):用「位址 + 長度」的描述符列表——更靈活,可描述任意長度的分散片段。適合複雜的 scatter-gather。

選哪個(常見誤區:以為 PRP 與 SGL 可隨意互換):取決於控制器能力與場景——不是隨意互換。常見:小 I/O 用 PRP(簡單),複雜/大型分散用 SGL(靈活)。控制器要支援 SGL 才能用。

對你產品極關鍵:PRP/SGL 正是 bio_vec(P5-T02)到裝置 DMA 的橋。回顧:bio 的資料分散在多個記憶體片段(bio_vec,scatter-gather);要讓 NVMe 裝置 DMA 存取這些片段,驅動把 bio_vec 轉成 PRP 或 SGL,裝置依此 DMA 搬資料(P6)。所以你產品的資料流是:bio(分散片段)→ PRP/SGL → 裝置 DMA。理解 PRP/SGL,你才懂「分散的記憶體怎麼被 NVMe 存取」這一步。

還有(常見誤區:忽略命令/完成項的嚴格大小與對齊):NVMe 命令是嚴格 64-byte、完成項 16-byte,且 SQ/CQ、PRP 等有對齊要求(回顧 P0-T04)。寫驅動時這些大小/對齊不能含糊。

一句話總結:NVMe 控制器管多個命名空間,用 host 記憶體裡的環狀 SQ/CQ 協作——host 把命令(64B)放進 SQ、按 doorbell(BAR 裡,按之前要 dma_wmb 屏障確保命令可見,P3-T11 命門)通知裝置,裝置 DMA 取命令執行、寫完成項(16B)進 CQ、發 MSI-X 中斷,host 靠 phase bit 判斷新完成項;資料記憶體位置用 PRP(頁列表)或 SGL(位址+長度)描述——正是 bio_vec 到裝置 DMA 的橋。這條 SQ→doorbell→CQ 流程是你產品資料路徑的根本。

常見誤區與踩雷提醒

誤區一:混淆 admin queue 與 I/O queue 的用途。 admin 管控制/設定/初始化(低頻);I/O 管實際讀寫(高頻、效能關鍵)。你的資料路徑走 I/O queue。

誤區二:忽略 completion 的 phase bit 是判斷新完成項的關鍵。 CQ 環狀、裝置非同步寫,host 靠 phase bit 區分新舊完成項(每繞一圈翻轉相位)。讀完成處理碼會看到它。

誤區三:以為 PRP 與 SGL 可隨意互換。 取決於控制器能力與場景。小 I/O 常用 PRP,複雜分散用 SGL(需控制器支援)。

誤區四:忽略命令/完成項的嚴格大小與對齊。 命令 64-byte、完成項 16-byte,SQ/CQ/PRP 有對齊要求(回顧 P0-T04)。寫驅動時不能含糊。

動手實作

環境:有 NVMe 的 Linux 機器,或 QEMU -device nvme(只在 VM)。

任務 A — nvme-cli 觀察(驗收點) 用 nvme-cli:nvme list(列出 namespace)、nvme id-ctrl /dev/nvme0(控制器資訊)、nvme id-ns /dev/nvme0n1(命名空間資訊)。列出控制器和至少一個 namespace 的關鍵資訊(如容量、block size、佇列數能力)。驗收:用 nvme-cli 列出控制器與至少一個 namespace 的關鍵資訊。

任務 B — 畫一次 NVMe I/O 流程(驗收點,核心) 畫出一次 NVMe I/O 的完整提交/完成流程,含:host 寫命令進 SQ → 屏障 → 按 SQ doorbell → 裝置取命令執行 → 寫完成項進 CQ → MSI-X 中斷 → host 用 phase bit 判斷新完成項 → 寫 CQ doorbell。驗收:畫出含 doorbell 與 phase bit 的完整流程。

任務 C — 說明 PRP vs SGL(驗收點) 寫一段話:PRP 和 SGL 的差異是什麼?各自適合什麼?驗收:說明 PRP 與 SGL 的差異與各自用途。(連結 P5-T02 bio_vec scatter-gather。)

任務 D(連結)— doorbell 屏障的重要性 寫一兩句話:為什麼在按 SQ doorbell 之前,要確保命令已對裝置可見(屏障)?(連結 P3-T11 的命門:否則裝置讀到還沒寫好的命令 → 資料毀損。)

延伸與銜接

  • 對應工作場景:直接對應——你產品把 NVMe queue I/O 餵給 GPU;理解 SQ/CQ、doorbell、PRP/SGL 是理解這條資料路徑與其 DMA 行為的根本。
  • 這課餵給未來的(I/O 物件流動主線):P5-T03 blk-mq 硬體佇列 → 本課 NVMe SQ/CQ → P5-T06 NVMe driver(nvme_queue 實作 SQ/CQ);doorbell 屏障 → 回收 P3-T11,用於 P6;PRP/SGL → P6 DMA scatter-gather 映射;命令對齊 → 回收 P0-T04。

P3-T06 · kernel 記憶體管理(一)—— page allocator 與 buddy system

一句話:kernel 管理實體記憶體的最底層,是以「頁(page)」為單位的配置器,用「夥伴系統(buddy system)」高效地切分與合併 2 的次方大小的記憶體塊。理解它,你才懂 DMA buffer 為何需要實體連續的 page、以及 dma_alloc_coherent 底層在做什麼。

為什麼要先學這個(導讀)

從這一課開始,連續兩課深入 kernel 的記憶體管理——這是你產品 I/O 路徑與 DMA 工作的核心基礎。這一課講最底層的「以頁為單位」的配置;下一課(P3-T07)講上層的 kmalloc/slab/vmalloc。

回顧 P1-T04:你學過虛擬記憶體、分頁(page,通常 4KB)、虛擬位址 vs 實體位址。那是「概念」層;這一課是「kernel 怎麼實際管理這些實體頁」。核心概念:

  • struct page:kernel 為每一個實體頁維護一個描述它的中介物件 struct page(記錄這頁的狀態、用途等)。注意:struct page 是「描述頁的中介物件」,不是頁的內容本身——這個區別很重要(常見誤區)。
  • buddy system(夥伴系統):kernel 用這個演算法管理空閒的實體頁,以 2 的次方個頁(order) 為單位配置——order-0 是 1 頁、order-1 是 2 頁、order-2 是 4 頁……它能高效地切分大塊、合併相鄰小塊(對抗碎片)。
  • page 層級的配置 API:alloc_pages/__get_free_pages/free_pages——直接配置整數個頁。

為什麼這對你是 scope: direct?因為 DMA buffer 常需要實體連續的 page(裝置用實體/匯流排位址直接存取記憶體,需要連續的實體空間,P6)。而 page allocator 正是 dma_alloc_coherent(DMA 記憶體配置)底層的基礎。理解 page allocator 與 buddy system,你才懂 DMA buffer 怎麼來、為什麼有「實體連續」這個要求。這一課也延續你那條「位址的真相」主線(實體 vs 虛擬 vs 線性映射位址)。

開始之前(前置確認)

  • 依賴:P3-T04(會寫 module)、P1-T04(虛擬記憶體、page、虛擬 vs 實體位址)。
  • 自我檢測: 1. 你還記得 P1-T04 的「虛擬位址 ≠ 實體位址」、page(4KB)的概念嗎?這課講 kernel 如何管理那些實體頁。 2. 你還記得 P0-T12 你手刻的記憶體配置器(free list、切分/合併)嗎?buddy system 是同類問題的 kernel 工業級解法。
  • 環境:QEMU 虛擬機。module 裡的配置實驗只在 VM。

核心內容

拆成這幾節:(1) struct page:每個實體頁的中介物件 → (2) node 與 zone(NUMA)→ (3) buddy system 與 order → (4) buddy 如何切分與合併 → (5) page 層級配置 API → (6) 實體 vs 虛擬 vs 線性映射位址,最後打通關。

1. struct page:每個實體頁的中介物件

kernel 為系統裡的每一個實體頁(physical page,通常 4KB)維護一個 struct page 結構,描述這頁的狀態與用途。

關鍵釐清(常見誤區):struct page 是「描述一個實體頁的中介物件」,不是那個頁裡裝的資料。它記錄這頁的後設資訊——目前被誰用、狀態、引用計數等。系統有多少實體頁,就有多少個 struct page(kernel 維護一個大陣列)。

這呼應你在 P2-T06 學的:page cache 的 XArray 就是「檔案 offset → struct page」的映射——那裡的 struct page 正是這裡說的中介物件,指向「快取了該檔案頁內容的那個實體頁」。

2. node 與 zone:記憶體的分區(NUMA)

實體記憶體在 kernel 眼中不是一整塊,而是分層的:node 和 zone。

兩層分區: - node(NUMA 節點):在 NUMA(非一致記憶體存取)系統裡,多個 CPU 插槽各有「離自己較近」的記憶體。存取自己 node 的記憶體快,存取別的 node 慢。kernel 把記憶體按 node 分,盡量讓配置「就近」(影響效能——忽略 NUMA 對效能的影響是常見誤區,尤其你的高效能 I/O 路徑)。 - zone(區域):每個 node 內再分 zone。歷史與硬體原因造成幾種:ZONE_DMA/ZONE_DMA32(低位址,給有定址限制的裝置 DMA 用)、ZONE_NORMAL(一般用途,大多數配置從這來)等。

你現在大致知道:配置記憶體時,kernel 從某個 node 的某個 zone 取頁。對 DMA,可能需要特定 zone(定址範圍)的記憶體——這在 P6 會更具體。

3. buddy system 與 order:以 2 的次方頁配置

kernel 管理「空閒的實體頁」用 buddy system(夥伴系統)。核心概念:記憶體以 2 的次方個頁 為單位配置,這個次方叫 order。

        O3["order-3 = 2³ = 8 頁(32KB)"]
        ODOT["... 以此類推 ..."]
    end

order-0 的空閒清單、order-1 的、order-2 的...
配置時找對應 order 的空閒塊"]
    orders --> NOTE
    style O2 fill:#e8a33d,color:#10100e
    style NOTE fill:#8a9a5b,color:#10100e

order-N 代表 2^N 個頁(驗收點):order-0 是 1 頁、order-2 是 4 頁、order-3 是 8 頁。buddy system 為每個 order 維護一個「空閒塊清單」——你要配置時,它從對應 order 的清單取一塊。

常見誤區:以 order 配置卻忘記 order 是 2 的次方頁數——你不能配「3 個頁」,只能配 order-1(2 頁)或 order-2(4 頁)。要 3 頁就得配 order-2(4 頁,浪費 1 頁)。理解這個,你才知道配置的粒度。

(這跟你 P0-T12 手刻的配置器是同類問題——管理空閒塊、切分、合併;buddy system 是 kernel 的工業級解法,用「2 的次方 + 夥伴」這個巧妙結構讓切分/合併極快,下一節看。)

4. buddy 如何切分與合併:對抗碎片

「夥伴」這個名字來自它的核心機制:每個塊都有一個同大小的「夥伴」,合併時只跟夥伴合併。

機制: - 配置(切分):若你要的 order 沒有空閒塊,buddy system 找一個更大的塊,對半切成兩個「夥伴」,一個給你(或繼續切),另一個留在較小 order 的空閒清單。 - 釋放(合併):釋放一塊時,檢查它的夥伴(位址相鄰的同大小塊)是否也空閒;若是,合併成一個更大的塊,再遞迴檢查更大塊的夥伴。

「夥伴」的精妙在於:夥伴的位址有固定的數學關係(只差一個塊大小,用位元運算就能算出夥伴位址),所以「找夥伴、判斷能否合併」極快。這讓 buddy system 能高效地對抗碎片(回顧 P0-T12 你手刻配置器時遇到的碎片問題、以及合併相鄰空閒塊的概念——buddy system 是這個概念的工業級、高效版)。

在 module 裡,你用這些 API 直接配置整數個頁:

    style NOTE fill:#c2603a,color:#f4ecd8

  • alloc_pages(gfp, order):配置 2^order 個頁,回傳指向第一個頁的 struct page *。
  • __get_free_pages(gfp, order):類似,但回傳「線性映射的虛擬位址」(見第 6 節),方便你直接讀寫那塊記憶體。
  • free_pages/__free_pages:釋放,要傳回相同的 order。

兩個要點: - 那個 gfp 參數是 GFP flags(下一課 P3-T07 詳述)——決定配置的行為(能不能睡眠等),在中斷/持鎖 context 極重要。 - 配置失敗回傳 NULL,務必檢查(常見誤區:配置失敗未檢查,回顧 P0-T06 也強調檢查 malloc 回傳)。

最後這一節延續你的「位址的真相」主線,釐清 kernel 裡幾種位址——這對 P6 DMA 極重要。

三種位址: - 實體位址:記憶體條上真正的位置(回顧 P1-T04)。 - 虛擬位址:經 MMU 翻譯的位址(回顧 P1-T04)。 - 線性映射位址(linear/direct mapping):kernel 把實體記憶體直接映射到一段 kernel 虛擬位址空間,兩者只差一個固定偏移——所以可以用簡單的加減(__pa/__va 之類)互轉,不必走完整的分頁表查找。__get_free_pages 回傳的就是這種線性映射位址,CPU 能直接用它讀寫對應的實體頁。

對你最關鍵的鋪墊(驗收點:區分實體位址與線性映射位址):線性映射位址讓 CPU 方便地存取實體記憶體,但它仍然是 CPU 視角的虛擬位址,不是「裝置看到的位址」。當你做 DMA,裝置直接存取記憶體時,它用的是另一種位址(dma_addr_t,匯流排/IOMMU 位址,P6 的核心主題)——你不能把 CPU 的虛擬位址(連線性映射位址也不行)直接交給裝置。這正是你「位址的真相」主線在 P6 的高潮:CPU 位址 ≠ 實體位址 ≠ 裝置位址。這一課先把「實體 / 虛擬 / 線性映射」三者釐清,為那個高潮鋪路。

一句話總結:kernel 為每個實體頁維護 struct page(中介物件),用 buddy system 以 order(2 的次方頁)為單位管理空閒頁——配置對半切、釋放跟夥伴合併以對抗碎片;alloc_pages/__get_free_pages 配置整數頁,而它回傳的線性映射位址雖方便 CPU 存取卻仍不是裝置看到的位址。這是 DMA buffer(需實體連續)與 dma_alloc_coherent 的底層基礎,也為 P6『CPU 位址 ≠ 裝置位址』的高潮鋪路。

常見誤區與踩雷提醒

誤區一:混淆 struct page 與頁的內容。 struct page 是描述實體頁的中介物件(後設資料),不是頁裡裝的資料。

誤區二:以 order 配置卻忘記 order 是 2 的次方頁數。 order-N = 2^N 頁。不能配「3 頁」,要 3 頁得配 order-2(4 頁)。理解配置粒度。

誤區三:配置失敗未檢查回傳。 alloc_pages/__get_free_pages 失敗回傳 NULL,務必檢查(回顧 P0-T06)。

誤區四:忽略 NUMA 節點對效能的影響。 NUMA 系統存取遠端 node 記憶體較慢。高效能路徑(你的 I/O)要注意配置的就近性。

誤區五:以為線性映射位址就是裝置能用的位址。 線性映射位址是 CPU 視角的虛擬位址,方便 CPU 存取實體記憶體,但不是裝置 DMA 用的位址(dma_addr_t,P6)。別把它直接給裝置。

動手實作

環境:QEMU 虛擬機。module 裡的配置實驗只在 VM。

任務 A — 配置不同 order 的 page(驗收點) 寫一個 module,在 init 裡: - 用 __get_free_pages(GFP_KERNEL, 0) 配置 order-0(1 頁),取得位址,寫入一些資料、讀回驗證,pr_info 印出配到的位址,再 free_pages。 - 同樣配置 order-2(__get_free_pages(GFP_KERNEL, 2),4 頁),寫入讀回,釋放。 全程檢查回傳是否為 NULL。驗收:成功配置 order-0 與 order-2、寫入讀回正確、釋放,全程無 dmesg 錯誤。

任務 B — 說明 order(驗收點) 用一句話說出 order-N 代表幾個 page。驗收:order-N = 2^N 個 page。

任務 C — 區分位址(驗收點) 用一句話區分「實體位址」與「線性映射位址」。(提示:實體是記憶體條上的位置;線性映射是 kernel 把實體記憶體直接映射到的虛擬位址,差固定偏移。)驗收:能區分兩者。

任務 D(連結)— 為什麼 DMA 要實體連續? 寫一兩句話:為什麼 DMA buffer 常需要實體連續的 page?(提示:裝置用實體/匯流排位址直接存取記憶體,需要連續的實體空間;這跟 page allocator 配置連續頁有關,P6 會深入。)

驗收與自我評分

驗收檢核點(量化,逐項通過): 1. ☐ 在 module 中成功配置 order-0 與 order-2(4 頁)記憶體、寫入並讀回正確、再釋放,全程無 dmesg 錯誤。 2. ☐ 說出 order-N 代表 2^N 個 page。 3. ☐ 用一句話區分實體位址與線性映射位址。

評分量表: - 60(及格):能配置/釋放 page。 - 80(熟練):能解釋 buddy/order。 - 100(精通):能說明 zone/NUMA 對配置與效能的影響。

延伸與銜接

  • 對應工作場景:直接對應——DMA buffer 常需實體連續的 page;理解 page allocator 是 P6 DMA 配置(dma_alloc_coherent 底層)的前置。
  • 這課餵給未來的:page allocator/buddy → P3-T07 slab(slab 從 buddy 拿頁再切小)、P6 DMA 配置;struct page → 回收 P2-T06 page cache、用於 P5 I/O;「實體/虛擬/線性映射位址」→ 你的位址真相主線在 P6 的高潮。
  • 下一步 → P3-T07 kernel 記憶體管理(二)——kmalloc / slab(SLUB) / vmalloc / GFP flags:你已經懂「以頁為單位」的底層配置。但你常需要的不是整頁,而是小物件(幾十、幾百 bytes)。下一課講上層配置器:kmalloc(配小塊、實體連續)、slab/SLUB(物件快取,從 buddy 拿頁再切成小物件)、vmalloc(虛擬連續但實體不連續)、以及極其重要的 GFP flags(GFP_KERNEL 可睡眠 vs GFP_ATOMIC 不可睡眠——在中斷/持鎖 context 選錯會死結!)。這直接關係你 I/O 路徑的物件配置與 DMA buffer。
